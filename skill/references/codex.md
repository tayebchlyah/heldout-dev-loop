## Setup contract

- Project agents: `.codex/agents/implementer.toml`, `.codex/agents/spec-tester.toml`, `.codex/agents/task-reviewer.toml`, `.codex/agents/planner.toml`.
- Review agents: `.codex/agents/final-reviewer.toml`, `.codex/agents/security-reviewer.toml`.
- Project hooks: `.codex/hooks.json`, plus scripts in `.dev-loop/hooks/codex/`: `gate.sh`, `deny-path.sh`, `git-guard.sh`, `acceptance-wall.sh`, `seal.sh`, `session-start.sh`, and `board.sh`. `PostToolUse` runs `board.sh post-tool` (matcher `Bash`). No `update_plan`: Codex 0.162.1 has no plan tool, the ledger is the record.
- `features.hooks = true`. Trust exact hook definitions through `/hooks` before relying on them. Codex skips an untrusted hook without a message: once `session-start.sh` is trusted, it names each project hook event with a hook entry that has no trusted hash (`check_setup.py --hooks-trust`). Tell the user to run `/hooks`.
- Automatic hooks run the kit code from a content-addressed copy, `${CODEX_HOME:-~/.codex}/dev-loop/kit/<H>/`, where `H` is the sha256 of the installed `.dev-loop/MANIFEST.json` that the hook command names (#227). A missing copy is filled from the first worktree of the hook process cwd, only when every byte matches `H`. A hook runs with `KIT_ROOT` (the copy) and `KIT_MAIN` (the source checkout, data only). When the kit cannot load (a bare first worktree, a missing or changed file), `git-guard.sh` and `acceptance-wall.sh` block with exit 2 and the block message; every other hook exits 0 with a `systemMessage` (D8). Seal, audit, search, setup and board use the kit copy's Python code with `-I`, while feature cwd and inputs stay on the feature. Stop and SubagentStop still run current feature tests automatically, with `GATE_SCOPE=changed`. The native `codex sandbox` launcher resolves trusted policy from main, includes managed requirements, retains read/deny rules and domain restrictions, removes arbitrary outside write grants and unix socket exceptions, keeps standard OS temporary write roots, makes a separate main checkout read-only, and grants feature writes with environment-file denies. Workspace writes and local server binding remain available under the normal kit policy. Gate temporary files use standard OS temporary folders, as in the native workspace profile. Missing or old Codex, invalid policy, unsupported inheritance/scopes, and failure before command start block the gate with `Sandbox startup failed` and a reason that says the sandbox could not start, an environment problem. A failed project command keeps its failure text. On macOS a path with a control character, quote, caret or bracket also blocks. On macOS, a deny-default Seatbelt adapter permits Chromium Mach rendezvous and process queries, and denies a terminal the gate did not open (#213). A private, signed copy of `ps` has no setuid bit; system `ps` stays unchanged. A live native Codex child owns the managed proxy. A trusted main-owned broker starts nested checks as separate confined processes because macOS rejects nested Seatbelt initialization. Each request keeps all ancestor filesystem and network limits. Broker requests never execute feature code on the host. Native configuration resolution supplies main and administrator policy; administrator restrictions still apply. Other platforms use the native launcher directly. No host fallback. Direct gates and Claude hooks stay unchanged. Upgrade changes Codex hook definitions: run `/hooks` to trust them again.
- The gate also denies each requirements `deny_read` path, which app-server does not report: `/etc/codex/requirements.toml` and the MDM `requirements_toml_base64` of `/Library/Managed Preferences`. An unreadable or invalid source blocks with `Sandbox startup failed`. Cloud requirements are not read.
- The active `dev-workspace` permission profile extends `:workspace` (writes stay in the workspace) and denies environment files. Its network goes through the Codex managed proxy (`features.network_proxy`, `mode = "full"`): no local unix socket (a container engine, so Docker cannot read `.env` or write outside the workspace), only the hosts of `[permissions.dev-workspace.network.domains]`. Host loopback TCP stays reachable (`allow_local_binding`): a container engine on loopback TCP is still a bypass. Docker work (`$release-audit`, a compose test stack) needs the `dev-docker` profile (extends `dev-workspace`, every local unix socket open: a full bypass), chosen at session start with `codex -c default_permissions=dev-docker`, never inside a session. It walls no agent: the walls are hooks. No legacy `sandbox_mode` key can remain in a loaded config layer.
- `Network access to "<host>" was blocked` is an environment failure, never a product failure: a stop item that names the host. The user adds the host to `[permissions.dev-workspace.network.domains]`; the agent never edits the profile.
- Walls: `acceptance-wall.sh` (PreToolUse `Bash|apply_patch|view_image|mcp__.*|read_mcp_resource|list_mcp_resources|list_mcp_resource_templates`) reads `agent_type`. `spec_tester` cannot name `src/`, `app/`, `backend/` or `frontend/`. Any other subagent cannot name `tests/acceptance`. The main session cannot `apply_patch` a file under `tests/acceptance/`. No caller can `apply_patch` an installed kit file (`.dev-loop/`, `.codex/rules/dev-loop.rules`, the kit agents, the kit skill folders `.agents/skills/<name>/` and `.claude/skills/<name>` of `dev-loop`, `pause`, `continue`, `release-audit`, `garden`, `release` and `release-notes`): kit files change only by `upgrade`. A relative path resolves against the cwd and each folder a `cd` or `pushd` of the command moves to. For `apply_patch` the paths are the file headers, never the patch body. Search rule: `acceptance-wall.sh` denies the `Bash` of every subagent but `spec_tester` a recursive search (`grep -r`, `rg`, `git grep`, `find`) whose root is `tests/acceptance` or a folder above it, unless it excludes the suite; the block names the scope. Engine: isolated `devloop.py search-wall` from the main checkout, with the requested feature cwd and input, skipped when none; a CLI error blocks. Not walled: wrappers (`xargs`, `env`, `sh -c`, `eval`) and `ls -R`, `tree`, `fd`, `ag`, `ack`, `git ls-files`; the audit path rule (a search output line that starts with a held-out file path) backs up the search tools. A hook denies with exit 2. `seal.sh start|stop|turn`: `start` records the subagent's start HEAD in `<git-dir>/dev-loop-subagents/<agent_id>.head`; the audit and the seal check at SubagentStop and Stop, a taint check at Stop. `stop_hook_active` true skips the block. `git-guard.sh`: only `spec_tester` runs `devloop.py seal`, and it cannot run a plain `git commit`. Minimum codex-cli 0.166.0.
- Tool walls (#97): MCP tools (`mcp__*`, `read_mcp_resource`, `list_mcp_resources`, `list_mcp_resource_templates`) are denied to `implementer` and `spec_tester`; any other subagent is denied an MCP call whose path fields (plus `filePath` and `uri`, a `file://` value by its path) name the held-out suite. `view_image` is walled by `path`: `spec_tester` the source folders, any other subagent the held-out suite. The main session keeps every tool, except that `exec_command` has no `tty` for any session (below). Code mode: no hook fires on `exec`, one fires on each inner tool call. No hook fires on `write_stdin`: `.codex/config.toml` sets `features.unified_exec_tty = false`, a setting of the whole project config, so `exec_command` has no `tty` for every session, the main one too (an interactive prompt or REPL through `exec_command` no longer works), and no shell stays open to type into (#140, checked in codex-cli 0.166.0; openai/codex#46372 asks for a hook); `check_setup.py` fails when it is not `false`. Not walled: for other subagents an MCP search tool, an MCP tool that runs code or reads a remote copy, a resource listing, an MCP path argument under a key outside that list. The audit reads `McpToolCall` results (output and search output) and code-mode results (`custom_tool_call_output`, output only). Native web search (#240): no hook sees it, and a role file ignores `web_search` (checked in codex-cli 0.166.0: a role with `web_search = "disabled"` still lists `web__run`), so `.codex/config.toml` sets `web_search = "disabled"`, a setting of the whole project config: no session has native web search, the main one too. An apps web tool (`mcp__codex_apps__*`) is an MCP tool: denied to `implementer` and `spec_tester`. Not walled: a shell fetch (`curl`, `gh api`) of the public repository, the network allows `github.com`; the audit reads its output.
- Gaps, written down, not closed: the agent can edit `.codex/hooks.json` and so turn a hook off (Codex skips a changed entry until `/hooks` trusts it, without a message); a `CODEX_HOME` the agent can write gives it the trust entries and the kit copy; a planted repo, gitfile or worktree can still change which repo or notes the trusted copy acts on (data, never code); a script that copies the seal value method; a script that reads a protected file and prints only a summary; a hook timeout; a rollout in Legacy mode (no audit); acceptance failure text that the controller gives to an implementer in a Stage 6 fix round; a tainted change squashed into another commit (its patch-id changes). Found in the build: a wrapped run (`env`, `uv run`, `python3 -I`, `command git commit`, `timeout 5 git commit`) passes the command-position seal rule, the seal check still catches the commit; `git patch-id` includes context lines, so a revert made after neighbouring edits may not close a taint record, and a rebase over changed context can close one; `seal.sh` exits 0 when `jq` is missing (a Stop hook cannot fail closed), `devloop.py gate` still checks; a variable that holds the script name (`D=devloop.py; python3 $D seal` across two segments) passes the seal-run rule, the seal check still catches the commit; a trailer key set through git config (`git -c trailer.<x>.key=Dev-Loop-Seal ... --trailer`) or a message file (`git commit -F file`) passes the typed-trailer rule, the seal check still rejects the forged value; a tainted agent can steer which of its commits the audit records by printing a commit line (D24 attribution), the audit and the PR diff still show the change; a folder held in a variable (`d=tests; cd $d`) passes the `cd` rule of the walls, the audit still records the read.
- Command rules prompt for direct pushes, every `git -C` form, and every `gh api` and `gh release` command (reads too: a prefix rule cannot see the method or the subcommand). They forbid direct hard resets and `rm -rf /`. The trusted Git hook provides defense in depth for wrapped commands.

## Delivery autonomy

- No ask tool outside plan mode: no ask wall needed.
- Waits: run `python3 .agents/skills/dev-loop/scripts/devloop.py gate --summary` directly as a background run and read its JSON: it keeps its own `log`, so no `logged` wrapper, no grep of escaped JSON. Exception to the SKILL.md rule to watch a long command: a background run that notifies when it ends counts as watched. Same for `ci wait --timeout <m>` (default 30): a command timeout of at least `<m>` plus 5 minutes.
- Hand-off at spec approval (SKILL.md Stage 2), each line in its own code block: 1 `/reasoning` with the medium level, 2 `/compact`, 3 `Start Delivery of <slug>`. Track S (Stage 1): `/reasoning` medium, then `Accept Track S`.

## Feature gate

Five phases, in order. First rebase onto `origin/main`, fresh stack, `GATE_SHA` = HEAD (SKILL.md Stage 6).

1. **Review wave, once.** First the second review (SKILL.md Stage 6), a background run watched to its end: `python3 .agents/skills/dev-loop/scripts/devloop.py logged --name second-review -- python3 .agents/skills/dev-loop/scripts/devloop.py second-review --harness codex` (reviewer `claude`). Then three reviewers, in parallel where the session allows it, otherwise in sequence. Each works in the feature worktree on `origin/main...GATE_SHA`: whole branch, report only, and returns its table (SKILL.md Stage 6 table contract). The reviewers are read-only: the controller saves each table with `python3 .agents/skills/dev-loop/scripts/devloop.py review-save --reviewer <reviewer>` from the feature worktree, table on stdin, to `<git-dir>/dev-loop/review/<reviewer>.md` (`<reviewer>`: `final-reviewer`, `code-review`, `security-reviewer`).
   - Custom read-only agent `final_reviewer`. In the CLI, Codex `/review` is the interactive equivalent.
   - Invoke skill `code-review` with fixed point `origin/main`.
   - Custom read-only agent `security_reviewer`.
   - Both custom reviewers run at `model_reasoning_effort = "high"` (their agent files).
   - The Claude reviewer runs inside `dev-workspace`: the managed proxy allows `api.anthropic.com`. It cannot write its config folder and does not need to.
2. **Triage, controller.** SKILL.md Stage 6. Read `seal`, `size` and `weakened` from the gate JSON: a `seal` or `size` violation is red. Merge: `python3 .agents/skills/dev-loop/scripts/devloop.py review-merge final-reviewer=<file> code-review=<file> security-reviewer=<file> [second-review:claude=<record>/output.md]`. Security verifier: a fresh `security_reviewer` per security finding. Prompt: the candidate-verifier prompt from `~/.agents/skills/security-audit/VALIDATION-AND-REPORTING.md` (Phase 3, "Candidate-verifier prompt"), plus the finding.
3. **Fix wave.** A new custom agent `implementer` per round, one file cluster at a time, for the Act On list: every defect, plus optional items the lead picks. Each passes `scripts/devloop.py gate --summary`: the process exits 0 (the project gate, `seal` and `size`).
4. **Drive.** SKILL.md Stage 6, `references/verify.md` section Stage 6. `scripts/devloop.py drive`, then the layout check: one fresh generic worker with the `drive.json` path. After the final full acceptance run: the closing drive (`references/verify.md` Stage 6 step 7).
5. **Acceptance loop.** SKILL.md Stage 6. Spec `acceptance: none`: skipped. `commands.acceptance` mapped: `python3 .agents/skills/dev-loop/scripts/devloop.py logged --name acceptance-run -- python3 .agents/skills/dev-loop/scripts/devloop.py acceptance [--failed]`, a background run watched to its end; read `guard` and `stale` from the JSON. `commands.acceptance` absent: runner lines from `stacks:`. Python: `pytest tests/acceptance -q --tb=no`. Go: `go test ./tests/acceptance/...`. UI: `npx playwright test tests/acceptance`. `commands.acceptance` absent: failures only by `--lf` or `--last-failed`.

Do not substitute Claude-only review, security, or verification slash commands in the Codex branch. Do not invoke `superpowers:verification-before-completion`. The Stop gate owns routine verification.

## Release audit

User-invoked only: `$release-audit` (kit skill `release-audit`), main session, at the commit to tag on `main`. Never in Delivery, never in a subagent: the `security-audit` skill starts its own agents. Target-controlled execution goes only through `sandbox-run.py` (OS-enforced container, no network). No engine or no image: skill stops (`no-sandbox`) unless user passed `--no-sandbox`, then source-only run, no target code. `dev-workspace` closes the engine (`sandbox.engine` false): restart with `codex -c default_permissions=dev-docker`. Cost: a run takes hours and costs tens of dollars (trial: 30 min, 19 USD, 2 subsystems, `quick`): the skill says so before it starts. Steps and CLI: the skill's `SKILL.md`.

`/release` (Codex: `$release`, kit skill `release`) runs the whole release and the audit steps inside it.
