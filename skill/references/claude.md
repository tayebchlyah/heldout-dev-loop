## Delivery autonomy

- Stages 3 to 7 start: `EnterWorktree` with the feature worktree `path` (create it first with `git worktree add --no-track -b <branch> .claude/worktrees/<slug> origin/main` when absent, run from the main checkout, one git command in its own Bash call; a session in another worktree: `ExitWorktree` with `keep` first. A path outside the project makes `EnterWorktree` ask the user, and a switch from one worktree to another is refused unless the target is under `.claude/worktrees/` of the same repository). The session cwd, and so each hook `cwd`, is then the worktree.
- Worktree session: in an `EnterWorktree` session, Claude Code refuses a Bash line that names git in a form it cannot verify. One git command per Bash call, no compound line around it. No word `git` in a heredoc, argument text, `--jq` or `--format` template: a commit message with it goes in a file (`Write`), then `git commit -F <file>`. Search with `grep -r --include=<glob> <pattern> <dir>`, never a glob after a `git` word.
- Waits: run `python3 .agents/skills/dev-loop/scripts/devloop.py gate --summary` directly, Bash with `run_in_background`, and read its JSON from the task output: it keeps its own `log`, so no `logged` wrapper, no grep of escaped JSON. Exception to the SKILL.md Monitor rule: the background task notifies when it ends, which counts as watched. Same for `ci wait --timeout <m>` (default 30): Bash with `run_in_background` and a `timeout` of at least `<m>` plus 5 minutes; a foreground Bash call stops at 10 minutes.
- Ask wall: `deny-ask.sh` (PreToolUse `AskUserQuestion`) denies the call in a feature worktree: a linked worktree, branch with `/`, `dev-loop.json` at its top. Decide and log with `devloop.py decide`, or stop and report a stop-list item. Fails open on an internal error: `main` keeps its questions.
- Limit: `pause.sh` (`StopFailure`, matcher `rate_limit`) writes the pause note through `devloop.py pause --event`. No intent fields: `/pause` adds them. Unconfirmed until a live check: a subscription usage limit arrives as `rate_limit`.
- Wake (same session, `/continue` or "continue"): `SendMessage` to each subagent that stopped during its work: it resumes with its full history. Source: the Claude Code docs; unconfirmed until a live check. A wake that fails: a fresh agent, full brief, plus "the uncommitted work in the worktree is yours, continue it".
- `/pause`: `TaskStop` on each running subagent; background `logged` runs stay alive.
- Stage 7 end: after the merge, `git fetch origin` and `metrics --write` in the feature worktree, then `ExitWorktree` with `keep`: the session cwd is the main checkout again. The final report suggests `/clear` before the next feature.
- Stage 7 log audit: the main transcript is `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/projects/*/$CLAUDE_CODE_SESSION_ID.jsonl`. The controller resolves it and passes the path.

## Feature gate

Five phases, in order. First rebase onto `origin/main`, fresh stack, `GATE_SHA` = HEAD (SKILL.md Stage 6).

1. **Review wave, once, in parallel.** First the second review (SKILL.md Stage 6): Bash with `run_in_background`, `python3 .agents/skills/dev-loop/scripts/devloop.py logged --name second-review -- python3 .agents/skills/dev-loop/scripts/devloop.py second-review --harness claude` (reviewer `codex`), then a Monitor on its log. Then, in one message, four Agent calls, all `general-purpose` with `model: opus` and `effort: high`. Three reviewers: native `code-review`, Pocock (Pocock = two desks: spec, standards), `security-review`. Each call works in the feature worktree on `origin/main...GATE_SHA`: whole branch, report only, no fixes. Each saves its table (SKILL.md Stage 6 table contract) with `python3 .agents/skills/dev-loop/scripts/devloop.py review-save --reviewer <reviewer>` from the feature worktree: the reviewer writes the table to a file with `Write` outside the repo (under `$TMPDIR`), runs `review-save --reviewer <reviewer> < <file>`, then removes the file. It saves to `<git-dir>/dev-loop/review/<reviewer>.md` (`<reviewer>`: `code-review`, `pocock-spec`, `pocock-standards`, `security-review`) and returns the path. Never `caveman:cavecrew-*`.
   - Invoke skill `code-review`, args `high <feature branch>`: effort `high`, the feature branch as target (no target reviews only the working diff). No `--fix`.
   - Invoke skill `security-review`. Review `git diff origin/main...GATE_SHA` from the feature worktree, not the working tree.
   - Pocock spec desk: read `mattpocock-skills:code-review` SKILL.md, do its spec desk only, fixed point `origin/main`.
   - Pocock standards desk: read `mattpocock-skills:code-review` SKILL.md, do its standards desk only, fixed point `origin/main`.
   - Both desks: direct Agent calls, no nested agents. A desk started inside a subagent reports after its parent hands back.
   - Sandbox gap: under the Claude Code sandbox the Codex reviewer fails (`failed` `exit <n>`: Codex cannot start its app-server). Never ask to leave the sandbox: report `second review: failed: exit <n>`.
2. **Triage, controller.** SKILL.md Stage 6. Merge: `python3 .agents/skills/dev-loop/scripts/devloop.py review-merge code-review=<file> pocock-spec=<file> pocock-standards=<file> security-review=<file> [second-review:codex=<record>/output.md]`. Security verifier: one fresh Agent call per security finding, `general-purpose`, `model: opus`, `effort: high`. Prompt: the candidate-verifier prompt from `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/security-audit/VALIDATION-AND-REPORTING.md` (Phase 3, "Candidate-verifier prompt"), plus the finding.
3. **Fix wave.** One new `implementer` per file cluster, one at a time, for the Act On list: every defect, plus optional items the lead picks. Each passes `scripts/devloop.py gate --summary`: the process exits 0 (the project gate, `seal` and `size`).
4. **Drive.** SKILL.md Stage 6, `references/verify.md` section Stage 6. `scripts/devloop.py drive`, then the layout check: one fresh Agent call, `general-purpose`, `model: sonnet`, with the `drive.json` path. After the final full acceptance run: the closing drive (`references/verify.md` Stage 6 step 7). Track S, after the drive: `python3 .agents/skills/dev-loop/scripts/devloop.py review-save --done` (the marker).
5. **Acceptance loop.** SKILL.md Stage 6. Spec `acceptance: none`: skipped. `commands.acceptance` mapped: Bash with `run_in_background`, `python3 .agents/skills/dev-loop/scripts/devloop.py logged --name acceptance-run -- python3 .agents/skills/dev-loop/scripts/devloop.py acceptance [--failed]`, then a Monitor on its log; read `guard` and `stale` from the JSON. `commands.acceptance` absent: runner lines from `stacks:`. Python: `pytest tests/acceptance -q --tb=no`. Go: `go test ./tests/acceptance/...`. UI: `npx playwright test tests/acceptance`. `commands.acceptance` absent: failures only by `pytest tests/acceptance --lf -q --tb=no`, `npx playwright test tests/acceptance --last-failed`. Every run after a fix repeats the stack reset first. Stale image run does not count.

No `/verify` step. `/verify` is a real bundled skill but user-invoked only; the model cannot call it. Playwright E2E is the model's live check. The user may type `/verify` after the gate.

Controller never edits `tests/acceptance/` in this stage. Read `seal`, `size` and `weakened` from the gate JSON in triage: a `seal` or `size` violation is red. An unplanned deployment or infra gap discovered by the gate is a new slice, not a fix round. Deployment or infra work explicitly named in the approved spec or plan stays in the current slice and is implemented normally.

Never invoke `superpowers:verification-before-completion`. The shell gate owns verification.
