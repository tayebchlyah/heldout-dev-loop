# status

- `status [--repo <path>] [--feature <slug>]`: `stage` (0 to 7, `shipped`, or `rebase` while a rebase is in progress), `check`, `next`, `feature`, `track`, `worktree`. `--repo` defaults to `.`. Spec frontmatter `shipped: <YYYY-MM-DD>` non-empty: `shipped`, no git check, left out of `features` (Stage 7 writes it and `pr: <url>` after the merge; not `status`: the notes vault owns it). No `--feature` on a branch without `/` (the default branch): Stage 1, plus `features`: each spec not shipped that is unapproved or has a local or origin branch `<prefix>/<slug>` or a worktree, with its `feature`, `stage`, `worktree`. An approved spec with neither is left out, stage not computed (`--feature <slug>` still resolves it). Same payload only: `review_due` `{last, days, log}` when the weekly review is due: `$NOTES/Gardener Log.md` table (header cells `Date` and `Verdict`, any order), newest `Date` (`YYYY-MM-DD`) of a `Verdict` `run` row 7 days or more before the local date (a future date: not due); no such row, or the log unreadable: `last`, `days` null; no log: due (nulls) only when a spec has `shipped:`. `next` unchanged. Track S: Stage 6 until `$(git rev-parse --git-dir)/dev-loop/review-done` exists. Spec frontmatter `acceptance: regression` or `none` (any case): no Stage 3 acceptance file needed, Stage 4 once the worktree exists. Stage 3 done: a file under `tests/acceptance/` named after the slug, or a commit in the history of `HEAD` that touches `tests/acceptance/` and has the message line `Acceptance: <slug>` (exact slug; a spec that only extends earlier files); no `origin/main` needed. An approved spec with no branch is `shipped` when `main` holds such a file, or `main` or `origin/main` holds such a commit. Optional `board` (`at`, `skipped`: the last board run skipped for a reason other than `busy`, `rebase`, `no-dev-loop`, `stage-0`, or crashed: `error`) and `kit_drift` (`worktree`, `main`, `direction`: `worktree-newer` when the worktree kit version is newer than the main worktree's; else `main-newer` when the `version` string of `.dev-loop/MANIFEST.json` at `refs/remotes/origin/main`, else `refs/heads/main`, as of the last fetch, is newer, `main` being that version; no ref, no MANIFEST, bad JSON or a non-string `version`: no `main-newer`; versions `x.y.z` or `x.y.z-rc.n`, an rc before its release; never fetches). Pause note: `<git-dir>/dev-loop/pause.json` of the worktree it reports on (the feature worktree, else the repo top level): `paused` (the note, `{"error": "unreadable pause note"}` when not a JSON object) and `next` `resume from the pause note`; a note with `reason` other than `manual` whose `session` is the current session (`CLAUDE_CODE_SESSION_ID`, else `CODEX_THREAD_ID`) is deleted instead, no field. On `main` without `--feature`, each `features` item whose worktree has a note gets `paused: true` (same rule). Only `status` deletes a note. `effort` `{level, want}` on every output: `level` is `CLAUDE_EFFORT` when it is `low`, `medium`, `high`, `xhigh` or `max`, else null; `want` is `high` for stages 1 and 2 and for `rebase` in the main worktree, `medium` for stages 3 to 7 and for `rebase` in a linked worktree, null for stage 0 and `shipped`. Reads local state only, never fetches. A tracked main worktree `dev-loop.local.json`: exit 1 with `error`; any other notes path failure stays stage 0 with the message in `next`.
