# merge-check

- `merge-check [--repo <path>] [--feature <slug>]`: the Stage 7 merge decision. Feature as `status` finds it (no `--feature`: the branch `<prefix>/<slug>`), `track` from spec `track:`, `S` with no spec. `<main-ref>`: `refs/remotes/origin/main`, else `refs/heads/main`, fully qualified (a local tag or branch `origin/main` cannot shadow it). `merge` and `merge_human_paths` from `git show <main-ref>:dev-loop.json`, never the branch. Reasons (`reason` plus its fields): `config-unreadable` (absent, not a JSON object, or a bad `merge` or `merge_human_paths` value, an item empty after strip or ending in `/` too: fails closed), `merge-human`, `track-l`, `human-path` (`path`, `pattern`: each path of `git diff --name-only --no-renames --ignore-submodules=none <main-ref>...HEAD` a pattern matches, first pattern wins), `config-changed` (`merge`, `merge_human_paths` or `file_size_exempt` (absent: `[]`; a bad value is compared as it is, never `config-unreadable`) in the `HEAD` copy differs; a `HEAD` copy absent or not parsing counts, unless `<main-ref>` has none of the three, an empty `file_size_exempt` counting as none), `no-review` (no reviewed head, a token that is not 7 to 40 hex characters, or not a commit), `unreviewed` (`commit`, `paths`: its code paths, all its paths when its diff fails)., `dropped` (`commit`: a reviewed commit with a non-empty patch-id that no landing commit carries and `git cherry <main-ref> <reviewed> <base>` does not mark `-`, for example a fix skipped in a rebase). With `config-unreadable`, `merge-human`, `human-path` and `config-changed` are not computed. Reviewed head: the sha of the last ledger line `Feature gate: green at <sha>` (Tracks M and L), else of `<git-dir>/dev-loop/review-done` (Track S). Each commit of `<main-ref>..HEAD` against its first parent: `git patch-id --verbatim` (whitespace kept, implies `--stable`) of its diff (`--no-ext-diff --no-textconv --no-color --no-renames --ignore-submodules=none -a`: a `.gitmodules` or user `ignore = all` cannot hide a submodule pointer move), reviewed when equal to one in `$(git merge-base <reviewed> <main-ref>)..<reviewed>`; an empty diff is skipped. Not reviewed with a code path, or a diff git cannot compute: `unreviewed`. Only test or doc paths: in `unreviewed_minor`, no block. Test or doc path: a segment `tests`, `test` or `docs`; a name `test_*.py`, `*_test.py`, `*_test.go`, `*.test.*`, `*.spec.*`, `README.md`, `CHANGELOG.md`. Any other path is code, kit Markdown too (a kit's Markdown is its behaviour). JSON `merge` (`human` when `reasons` is not empty, else `auto`), `reasons`, `reviewed` (the full sha, resolved in the feature worktree, or null), `unreviewed_minor` (`commit`, `paths`), `feature`, `track`. Bytes that are not UTF-8 in the branch `dev-loop.json` (counts as not parsing), a path name or the ledger never crash it. Exit 0. Exit 1 with `error`: no feature (a branch without `/` and no `--feature`, or no branch `<prefix>/<slug>`), notes path unresolved, no `<main-ref>`, a git failure reading `HEAD`, a path list or a commit list (worktree folder gone, no merge base: fails closed, no `merge`). Exit 2 usage.
