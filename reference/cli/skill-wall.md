# skill-wall

- `skill-wall`: stdin one Claude PreToolUse hook JSON object (`tool_input.skill`, `cwd`). JSON `{"deny": bool, "reason": string|null}`; `reason` is one of the reasons below when `deny` is true. Exit 0 for allow and deny, 2 on a usage error. Input that is not a JSON object: `deny` true, `reason` `not in walled_skills`. Claude only: Codex has no `Skill` tool.
- Who: the caller checks the agent. Only the arm `implementer:Skill` of `deny-acceptance-to-subagents.sh` runs it, and only for a name that is not one of its 3 fixed names.
- Folder: hook `cwd`, else `$CLAUDE_PROJECT_DIR`. Checkouts: the worktree of the folder, the worktree of `$CLAUDE_PROJECT_DIR` (the session start folder, `Skill` loads from it) and the main worktree. Main ref: `refs/remotes/origin/main`, else `refs/heads/main`.
- Conditions, in order; the first that fails names the reason:
  1. The `walled_skills` list of `dev-loop.json` at the main ref holds the name, and the name fits `^[a-z0-9][a-z0-9-]{0,63}$`. Else `not in walled_skills`. No folder, no main ref, a file that is not JSON or a value that is not a list: the same.
  2. `.claude/skills/<name>/SKILL.md` exists at the main ref. Else `no copy at the main ref`.
  3. Each checkout holds the same `SKILL.md` bytes and the same link text. Else `differs from the main ref`. `Skill` loads from the session start folder, so its worktree is a checkout too.
  4. The scan of the main ref copy is clean. Else `context: fork`, `shell line`, `hooks key`, `at mention` or `frontmatter shape`.
- Link: when `.claude/skills/<name>` has mode `120000` at the main ref, follow it one level, relative to `.claude/skills/`. The target must stay in the repository and not be the repository top, and the `SKILL.md` under it must be a regular file. A link inside the target, an absolute link or a target outside: `no copy at the main ref`. Each checkout must have the same link.
- Scan, in order: frontmatter key `context`: `context: fork`; `` !` `` or ` ```! ` anywhere in the file: `shell line`; frontmatter key `hooks`: `hooks key`; an `@` byte anywhere in the file: `at mention`; an odd frontmatter shape: `frontmatter shape`. The frontmatter is the Claude Code fence: `---`, optional white space (U+FEFF counts), a line end, then everything up to the first literal `---` anywhere, also mid-line, at the file start only (one BOM stripped); no match, no frontmatter. The shape is odd when the first non-comment line starts with a space or tab, or any non-comment line at column 0 is not a plain `key:` (tags, anchors, `?`, aliases, `<<`, flow maps, quoted keys, escapes). A key counts plain or quoted, at a line start or after `{` or `,`, with any value. An `@` mention in a body attaches a file with no `Read` call, so any `@` denies, on purpose. The rules are wide on purpose: a false match denies the skill, and the agent reads the `SKILL.md`. The fence copies one Claude Code 2.1.310 regex and can drift on an upgrade.
- Gaps: `Skill` serves a cached body until the skill watcher reloads it, so a copy edited, reloaded, then restored passes the check and loads the edited text; a `skills:` field in an agent file preloads the text with no `Skill` call (kit agent files have none); a session started in a subfolder loads no root settings, so it has no wall; a personal skill with a listed name, a change of the file between the check and the load, a local move of the main ref, a branch edit of the kit `devloop.py`. Under a git attribute or `core.autocrlf` that changes line ends, the checkout differs from the blob: a deny.
- Callers: `deny-acceptance-to-subagents.sh`. CLI `.agents/skills/dev-loop/scripts/devloop.py` under the git top of `cwd`, else `$CLAUDE_PROJECT_DIR`; none, a non-zero exit or output that is not a JSON object: the wall denies. `check_setup.py` and `merge_check.py` import the module.
