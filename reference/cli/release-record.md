# release-record

- `release-record --run <folder> [--base <sha>] [--harness claude|codex] [--repo <path>]`: writes the audit result into the project note in one write: a D4 line per `confirmed` and `needs_validation` record not already open (by fingerprint) under `### Release audit Run <N>, <date>` in `## Deferred`, a `## Gardener` hardening line, the `## Release audits` record line. Severity bar: a `confirmed` record whose `severity.overall_severity` is `low` or `informational` gets a `## Gardener` line `- <date> (security, low, Run <N>): <title>. Fingerprint `<fp>`. Details: Security Audit/Run <N>/FINDINGS-DETAIL.md.` instead (no fingerprint: that part left out), before the hardening line; any other value, or none: `## Deferred` (fails closed). A low fingerprint already in a `## Gardener` line or an open `## Deferred` item: no line, listed in `skipped`. Carry: a `needs_validation` record whose fingerprint is not open, and whose last `## Deferred` item of that fingerprint (file order, any verdict) has a last ruling `accept`, gets the sub-bullet `  - Ruling <today>: accept carried from the <ruling date> ruling (<prior run>): fingerprint and trace files unchanged since <7 hex>.` under its line when the prior commit (the `## Release audits` record sha of the prior item's run) is a commit, every unique `trace[].file` is a relative blob path with no `..` part at the run commit, and `git diff --quiet <prior> <run commit> -- <file>` exits 0 for each (repo top, literal pathspecs); else the line is open and listed in `reopened`. A `confirmed` or low record, or a last ruling other than `accept`: no carry. The record line counts every `confirmed` record. JSON `record`, `deferred` (every item line, carried ones too, never the sub-bullet), `carried` (`[{fingerprint, from, ruling}]`: `from` the prior run, `ruling` the date of its last ruling), `reopened` (`[{fingerprint, why, files}]`: `why` `no-commit`, `bad-trace` or `changed`, checked in that order; `files` the changed trace files, sorted, else `[]`), `low` (the Gardener lines of low records), `skipped`, `gardener`. Exit 1 with `error`, nothing written: `bad-run` (not `$NOTES/Security Audit/Run <N>`), `bad-base` (`--base` not 40 hex; or a current record exists and `--base` differs from the base `release-plan` gives for the run commit, absent included: JSON `expected_base`; with no current record any `--base` is kept), `no-project-note`, `run-incomplete` (JSON `run_status`; the skill reads `incomplete_reason` from the run's `run-metadata.json`), `invalid-run` (`tail`: a bad `run-metadata.json` or `findings.json`, or the skill's `validate-findings.cjs` or `validate-coverage-ledger.cjs` fails or cannot start), `already-recorded`, `cannot read <note>: <ExcType>`. While `$NOTES/security-audit` exists (the old layout): exit 1, `{"error": "old-notes-layout", "fix": "devloop.py notes-migrate"}`. Exit 2 usage.
- `release-record --fix-wave --issue <n> [--issue <n> ...] [--repo <path>]`: records the end of the fix wave of the current record R (the last record line): writes `- <today> <R run> fix wave at <HEAD sha>: #<a>, #<b>` (issues unique, ascending) as the last bullet of `## Release audits`, one write under the same lock. JSON `wave` (the line). Code commit: a commit of `R..HEAD` (`git log` order) whose diff against its first parent changes a path that is not a test or doc path and that the `ci-skip` rules do not allow (`reference/cli/ci-skip.md`; a bad `version_files`: every non-test, non-doc path; a root commit: every path). Names an issue `n`: the subject holds `#n` not followed by a digit. Exit 1 with `error`, nothing written, checked in this order: `no-audit` (no record line), `wave-exists` (a wave line names R's run), `not-descendant` (R sha is not a strict ancestor of HEAD), `foreign-commit` (a code commit that names no `--issue`; `commits`: `[{sha, subject}]` in `git log` order), `unfixed` (an `--issue` no subject of `R..HEAD` names; `issues`: ascending ints). Also `no-project-note`, `cannot read <note>: <ExcType>`, the old layout as above. Exit 2: `--fix-wave` with `--run`, `--base` or `--harness`, or with no `--issue`; `--issue` without `--fix-wave`, or not a positive int; no `--run` and no `--fix-wave`. `release-check` reads the wave (`reference/cli/release-check.md`).
