# release-record

- `release-record --run <folder> [--base <sha>] [--harness claude|codex] [--repo <path>]`: writes the audit result into the project note in one write: a D4 line per `confirmed` and `needs_validation` record not already open (by fingerprint) under `### Release audit Run <N>, <date>` in `## Deferred`, a `## Gardener` hardening line, the `## Release audits` record line. Severity bar: a `confirmed` record whose `severity.overall_severity` is `low` or `informational` gets a `## Gardener` line `- <date> (security, low, Run <N>): <title>. Fingerprint `<fp>`. Details: Security Audit/Run <N>/FINDINGS-DETAIL.md.` instead (no fingerprint: that part left out), before the hardening line; any other value, or none: `## Deferred` (fails closed). A low fingerprint already in a `## Gardener` line or an open `## Deferred` item: no line, listed in `skipped`. The record line counts every `confirmed` record. JSON `record`, `deferred`, `low` (the Gardener lines of low records), `skipped`, `gardener`. Exit 1 with `error`, nothing written: `bad-run` (not `$NOTES/Security Audit/Run <N>`), `bad-base` (`--base` not 40 hex; or a current record exists and `--base` differs from the base `release-plan` gives for the run commit, absent included: JSON `expected_base`; with no current record any `--base` is kept), `no-project-note`, `run-incomplete` (JSON `run_status`; the skill reads `incomplete_reason` from the run's `run-metadata.json`), `invalid-run` (`tail`: a bad `run-metadata.json` or `findings.json`, or the skill's `validate-findings.cjs` or `validate-coverage-ledger.cjs` fails or cannot start), `already-recorded`, `cannot read <note>: <ExcType>`. While `$NOTES/security-audit` exists (the old layout): exit 1, `{"error": "old-notes-layout", "fix": "devloop.py notes-migrate"}`. Exit 2 usage.
