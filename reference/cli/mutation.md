# mutation

- `mutation --head <rev> [--base <rev>] [--main <branch>] [--repo <path>] [--run] [--entry <path>] [--only <unit> ...]`: find the changed lines in the critical files of each `mutation` entry of `dev-loop.json`; with `--run`, run each entry's adapter, check its output, classify the survivors and print the report. `--base` default: the merge base of `--main` (default `main`) and `--head`. `--repo` default: the cwd. `--head` and `--base` are resolved to full shas.
- No `--run`: `{"base", "head", "entries": [{"path", "adapter" or "command", "files"}], "outside": [<file>], "none": [<path>]}`, exit 0. No adapter runs, except the `run` false call of the rerun rule. `files`: `{"<file relative to the entry folder>": [[start, end], ...]}`; every entry is listed, its `files` may be `{}`.
- `--run`: `{"status", "base", "head", "report", "entries": [{"path", "status", "cause", "mutants", "need_tests"}], "outside", "none"}`. Exit 0 for `pass` and `survivors`, 1 for `setup` and `failed`, 2 for a usage error. `cause`: null or one line. `need_tests`: the number of units listed under `units that need one unit test`.
- Invalid `mutation`: `{"status": "setup", "cause"}`, exit 1, with or without `--run`. An unknown adapter: `cause` `mutation entry <path>: unknown adapter <name>`; any other shape fault: `mutation in dev-loop.json is invalid: <rule>`.
- Usage error: `{"error": "<message>"}`, exit 2. Until the run is built, `--run` exits 2 with `{"error": "--run: not built"}`.
- Report, in this order, paths relative to the repo root, units and mutants sorted by file, line and diff, each control character of a unit, `detail`, `reason` or `cause` replaced by a space: `base: <sha>`, `head: <sha>`; for each entry: `entry <path>: <adapter or command> <status>`, `<path> mutants run: <n>`, `<path> units that need one unit test: <n>` (each unit at 2 spaces, under it each `<file>:<line> survived` or `<file>:<line> no tests` at 4 spaces, under it each diff row at 6 spaces), `<path> message-only survivors, to Deferred: <n>` (each `<unit> <file>:<line>` at 2 spaces, its diff rows at 6), `<path> inconclusive: <n>` (each `<detail>: <n>` at 2 spaces, `inconclusive` when no detail), `<path> not covered by the selection: <n>` (each `<file>:<start>-<end> <reason>` at 2 spaces), and `<path> <status>: <cause>` when the entry has a cause; then `outside the critical modules: <n>` (each file at 2 spaces), then each `mutation: none for <path>` line.

## Rules

- M1 config: opt in. No `mutation` key equals `false`: off. A list of entries `{path, adapter, critical}` or `{path, command, critical}`, no other key, exactly one of `adapter` and `command`, each a non-empty string. `path`: `.`, or a folder by the `source_dirs` entry rules, a folder at `--head`. `adapter`: `mutmut`, `stryker` or `mutago`. `critical`: a non-empty list of non-empty globs relative to `path`, one at least without `!`. No duplicate path (NFC, case-folded). Read from `dev-loop.json` at `--head`, as `stacks`.
- M2 globs: the kit matcher, case-sensitive. `*` and `?` stay in one path segment, `**` matches zero or more segments. A file is critical when a glob without `!` matches it and no `!` glob matches it.
- M3 selection: `git -c core.quotePath=false diff --no-ext-diff --no-color -U0 -M --diff-filter=AMR --src-prefix=a/ --dst-prefix=b/ --ignore-submodules <base>..<head>`. Binary files and files with no changed line are not selected. A changed file belongs to the deepest entry whose path holds it (exact, case-sensitive). Critical: selected with the head-side line ranges of its hunks, 1-based, inclusive, sorted, adjacent and overlapping ranges merged. A deleted line counts as a change of the line above it (line 1: line 1). Not critical: `outside`. Under no entry: not listed.
- M4 protocol: one-way door, project adapters depend on it. Each entry with a selected file runs in the entry folder, one after the other: a built-in as the kit's Python on `scripts/mutation/<adapter>.py`, a `command` through `sh -c`. Stdin: `{"protocol": 1, "run", "base", "head", "files", "only"}`. Stdout: one JSON object `{"units", "mutants", "not_covered"}`. Exit 0 done, 2 setup missing or broken, other: the tool failed.
- M5 to M10 (fields, output check, classification, rerun, integrity, status): built with `--run` in later tasks of the feature.
- P3 off: empty `entries`, `outside` and `none`; with `--run`, `{"status": "pass", ..., "report": "mutation: off"}`.
- P4 `none`: each `stacks` path at `--head` (ignored when invalid) that no entry path equals or holds.
