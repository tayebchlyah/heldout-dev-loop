# audit

- `audit`: SubagentStop hook JSON on stdin (`agent_id`, `agent_type`, `agent_transcript_path`, `cwd`). Compares the subagent's tool output with the files it must not read (`spec-tester`: the `source_dirs` entries of `dev-loop.json` at the main ref that are not in a top-level dot folder, matched from the repo root with case folding, and every file in a top-level dot folder leaves the comparison; no key, or an invalid key: `src/`, `app/`, `backend/`, `frontend/`; any other: `tests/acceptance/`). 2 or more distinct distinctive lines (30 characters or more): a taint record in `<git-dir>/dev-loop/taint.json`; no `<agent_id>.head`: the range starts at `<base>`, else the root. A re-stop replaces the agent's record or skip. JSON `taint` (record or null), `skipped`. The path rule (any subagent but `spec-tester`): a line of a search output (a `Grep` or `Glob` result, or a `Bash` call or Codex `CommandExecution` whose command holds `grep`, `egrep`, `fgrep`, `rgrep`, `rg` or `find` as a whole word; a Claude `tool_result` is paired with its call by `tool_use_id`) that starts with the path of a held-out file (`tests/acceptance/<rest>`, with any `<dir>/` before it, or `acceptance/<rest>`, `./acceptance/<rest>`; then the end of the line, `:`, `-`, a NUL or whitespace) taints alone; one path is enough. Listings and gate output are not search outputs. A `grep`, `egrep`, `fgrep` or `rg` with no file or folder operand, after a `|`, is a filter, not a search (`git ls-files | grep tests`); `find`, `git grep`, `-r` and any command it cannot parse as a filter are searches. A record holds `paths` (the matched suite paths, sorted, at most 3; `[]` for a line-only taint); an older record without it still loads. Exit 0, also on a skip.
- Tool results (#97): a Claude `LSP` or MCP result (`mcp__*`, `ListMcpResourcesTool`, `ReadMcpResourceTool`, `ReadMcpResourceDirTool`) is output and search output. `Monitor` counts as `Bash` for the search test. A `Monitor` task notification (an `attachment` line, `queued_command`, `commandMode` `task-notification`) is paired with its `Monitor` call by `<tool-use-id>`: each `<event>` text is output, and search output when that call is a search; a notification of any other call counts as nothing. Codex: an `McpToolCall` result (`item.result.content[].text`) is output and search output; a code-mode result (`response_item` `custom_tool_call_output`, `output[].text` or a string) is output only. Use of a tool alone records nothing.
