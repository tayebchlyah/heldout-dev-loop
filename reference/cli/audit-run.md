# audit-run

`audit-run <step> --run <folder> [--repo <path>] ...`: the parent-side steps of a release security audit run, one per call: `seed`, `units`, `brief`, `check`, `promote`, `fold`, `findings`, `report`, `status`. One JSON object on stdout; exit 0, 1 (JSON `error`), 2 (usage). `--run` must be `$NOTES/Security Audit/Run <N>`, else `bad-run`. Every step but `seed` needs `run-metadata.json` and `audit-run.json`, else `not-seeded`. `--repo` (default `.`) finds the notes folder. The trusted state of the steps is `<run>/audit-run.json`, written only by the steps (temp file and rename); `agents/<id>/brief.json` is written for the agent and never read back. The skill text and validators come from the folder `plan.json` `skill` names (`security-audit` skill, upstream pin `c1c8a8c1471069fb0e188eeaff69b8e8db6564a8`, `version` in `upstream.json`). Every ledger write passes `validate-coverage-ledger.cjs` on a temp file before it replaces `coverage-ledger.json`; a fail: `ledger-invalid` (`tail`), nothing written. No step writes outside the run folder.

## seed

`seed`: reads `<run>/plan.json` (written by `release-plan`); writes `coverage-ledger.json`, `run-metadata.json` (`run_id`, `repo`, `target`, `source_ref` `{commit: plan head, dirty: false}`, `profile`, `budget`, `scope_paths` `{scope, exclude}`, `execution_policy: "sandboxed-source-and-local-only"`, `selected_companion_files`, `prior_run_paths`, `shared_file_owners`, `result_transport`, `run_status: "in_progress"`) and `audit-run.json`. JSON `run`, `prior` (`Run <k>` or null), `carried` (coverage ids), `touched` (`[{coverage_id, paths}]`), `units` (ledger length).

- Prior run: the highest `Run <k>` below this one whose `run-metadata.json` `run_status` is `complete` or `incomplete` (an incomplete run is continued). An incomplete prior with no `findings.json` has no records.
- Carry, per prior unit, first match: a linked `confirmed` record: `prior_confirmed_same_source` when no `trace[].file` of it changed in `<prior commit>..<head>`, else `prior_confirmed_changed_source`; a linked `needs_validation` record: `prior_needs_validation`; a linked fingerprint with no record: `prior_deferred`; status `deferred`, `blocked`, `out_of_scope`: `prior_<status>`; `planned`, `in_progress`: `prior_deferred`. Not carried: `covered`, `not_applicable`, linked only to `rejected`.
- A carried unit keeps its id, refs, labels, `starting_paths`, block fields and `resolved_prior_leads`; `prior_fingerprints` its old `result_fingerprints`; `planned`, wave 1, no owner, no evidence. No starting path in scope: `out_of_scope`, `unresolved` `["outside the run scope"]`.
- Scope: `whole`: every path but `exclude` and `tests/acceptance/`; `<base>..<head>`: the paths of `git diff --name-only <base> <head>`, less those. A path or a folder over one of them is in scope.
- `touched`: each prior `covered` unit with a `reviewed_paths` entry changed in `<prior commit>..<head>`, with those paths.
- Errors, nothing written: `already-seeded` (`run-metadata.json` exists), `no-plan`, `prior-invalid` (`file`: an unreadable prior ledger or `findings.json`), `git-failed`, `ledger-invalid`.

## units

`units --add FILE`: `FILE` a JSON array of units: `canonical_refs` (`surface`, `boundary`, `subsystem`, `attack_class`, optional `lifecycle`; absent: the four labels), the labels, `starting_paths` (non-empty, relative, no `.`, `..` or empty part), `ordinary_attack_class_block`, `selected_companion_blocks`, `excluded_blocks` (`[{block, reason}]`), `prior_status` (absent: `new` with a prior run, else `none`), optional `status` (`planned`, `not_applicable`, `out_of_scope`, `deferred`) and `reason` (needed when not `planned`; it becomes `unresolved`). Each ref: NFC, no outer whitespace, no control or invisible character, a visible character. The id: each ref percent-encoded (UTF-8, `A-Za-z0-9-._~` kept), joined with `::`. JSON `added` (ids). The ledger stays sorted by id; `run-metadata.json` `selected_companion_files` follows the companion blocks of the ledger. Errors, nothing written: `invalid` (`entry`: the index, or null for a file that is not a readable JSON array; `errors`), `duplicate` (`coverage_id`: twice in the file, or already in the ledger), `ledger-invalid`.

`units --update FILE`: `FILE` a JSON array of `{coverage_id, starting_paths?, ordinary_attack_class_block?, selected_companion_blocks?, excluded_blocks?}`; refs and id never change. JSON `updated`. Errors, nothing written: `invalid`, `unknown-unit`, `not-planned` (the unit is not `planned`, or an open brief holds it), `ledger-invalid`.

## brief

`brief --kind hunter --units ID [ID ...]` | `--kind critic [--final]` | `--kind verifier --fingerprint FP` | `--kind recheck --fingerprint FP`: JSON `agent`, `prompt` (`<run>/agents/<id>/prompt.md`), `result` (`<run>/agents/<id>/scratch/result.json`). The id: `h`, `c`, `v`, `r` per kind, then a two-digit number counted per kind in the run (`h01`, ..., `h100`). Writes `agents/<id>/brief.json` (`kind`, `units` or `fingerprint`, `final`; for the agent, never read back), `prompt.md`, empty `scratch/` and `artifacts/`, and the brief in `audit-run.json` as `open`. A hunter brief sets its units `in_progress`, owner the id; a verifier brief sets the planned carried units of its fingerprint (`prior_confirmed_same_source`, `prior_needs_validation`, in scope) `in_progress`, owner the verifier.

The parent writes `context.md` and `architecture.md` in the run folder first; every brief holds them verbatim (a recheck brief: `context.md` only). Prompt parts, each a `## ` heading:

- Hunter: role, `context.md`, `architecture.md`, each unit's assignment fields (JSON), each selected block (D8 refs: the `## Name` or `## Name (...` section, else the `**Name**` paragraphs), excluded blocks with reasons, the `HUNTING.md` fences under `#### Core hunting method`, `#### Promotion procedure`, `#### Core validation rules`, carried exclusions (fingerprint, title, root cause of each same-source prior confirmed record), peer coverage ids, `## Structured hunter result`, the `confirmed` and `needs_validation` branches of `report-schema.json`, the result path, the limits, the `check` line.
- Critic: role, `context.md`, `architecture.md`, `## Coverage-critic waves`, the ledger, the candidates (fingerprint, proposed verdict, title, hunter), the prior gap summary, the `notes` rule, the result path, the `check` line.
- Verifier: role, `context.md`, `architecture.md`, the two fences under `#### Candidate-verifier prompt` of `VALIDATION-AND-REPORTING.md` (prompt, promotion procedure), profile `quick`: `### Phase 5` up to `### Phase 6`; the candidate, the linked unit checks and artifacts, the `Validation rules` blocks of the linked units' companion files, the three verdict branches, the prior record of the fingerprint, the result path, the limits, the `check` line. Never another verifier's result.
- Recheck: role, `context.md`, `### Phase 5` up to `### Phase 6`, the final record, the three verdict branches, the promotion fence, the result path, the `check` line.

Errors, nothing written, in this order: `no-context`, `no-architecture` (`file`: no regular file); `not-planned` (`units`: unknown or not `planned`), `carried` (`units`: verifier work, D17a); `unknown-fingerprint` (verifier: no candidate and no carried unit; recheck: no final record); `skill-changed` (`file`, `section`); `ledger-invalid`. Exit 2: `hunter` without `--units` or with `--fingerprint` or `--final`; `critic` with `--units` or `--fingerprint`; `verifier`, `recheck` without `--fingerprint` or with `--units` or `--final`.

## check

`check --agent ID`: reads `agents/<id>/scratch/result.json` (every folder part and the file opened no-follow) and checks it against the rules of the brief kind; the kind comes from `audit-run.json`, never `brief.json`. Exit 0 `{ok: true}`; else exit 1 `{ok: false, state, errors}` (at most 50): `missing` (no file), `invalid` (a link, not a regular file, over 5 MiB (not parsed), not JSON, not an object, or a rule broken). An agent runs it on its own result before it hands back; `fold` runs it first. Errors: `unknown-agent`.

- Every check: `agent_id` the brief's, non-empty `reviewed_paths` (relative, no `.`, `..` or empty part), visible `invariant` and `result`; `source`: `artifact` null; `local`: `artifact` `agents/<id>/artifacts/<rel>` with a regular single-link file `agents/<id>/scratch/<rel>`.
- Hunter: each assigned id once in `units`, no other id; `covered` (paths and checks, no `unresolved`, no fingerprint), `candidate` (paths and checks, a fingerprint), `blocked` (paths, checks, `unresolved`, no fingerprint); unit `reviewed_paths` the union of its checks'; fingerprints match `^[A-Za-z0-9][A-Za-z0-9._:/@+-]*$` and name a candidate of the result or the run; candidates `confirmed` or `needs_validation`, unique, all through `validate-findings.cjs` (`proposed_verdict` as `verdict`); `hardening` strings; `uncovered` entries: the four labels, `starting_paths`, block fields, a `reason`.
- Critic: `missing_units`, `reassign_ids` and `resolved_prior_leads` all present as lists (absent: `invalid`); `missing_units` as `uncovered`; `reassign_ids` units now `blocked`, `covered` or `candidate`, none twice; `resolved_prior_leads` fingerprints linked to a unit; `stop` true only with both lists empty; `notes`: a reason for each reassign id and each resolved lead.
- Verifier: `decision` a verdict, `record.verdict` equal to it, the record through `validate-findings.cjs`, a non-empty `checks`; a record fingerprint other than the brief's must be new to the run (not in `final`, `candidates`, `renamed` or a unit's fingerprints), else `record.fingerprint: <fp> is another fingerprint of the run`.
- Recheck: `verified` with the brief's `fingerprint`, or `replace` with a `reason` and a `record` of the same fingerprint through `validate-findings.cjs`; optional `checks`.

## promote

`promote --agent ID`: copies each file the `local` checks of the agent's result name, `agents/<id>/artifacts/<rel>` from `agents/<id>/scratch/<rel>`; the result is the allowlist, no path argument. The result must be one readable JSON object (`check` kind rules are not needed: a bad file is refused file by file). Per file: `rel` relative, no `.`, `..` or empty part; each folder opened no-follow from the scratch root; the leaf opened no-follow and non-blocking; a regular file, link count 1, at most 256 KiB, the agent total at most 1 MiB (already promoted files count); size and identity checked again after the read; the destination folders opened no-follow (created when missing), the file created exclusive and no-follow. A failed file is not copied, the others go on. JSON `promoted` (paths), `rejected` (`[{path, reason}]`, reason `unsafe-path`, `missing`, `link`, `not-regular`, `hard-linked`, `too-large`, `agent-limit`, `changed`, `exists`: an artifact is never overwritten). Errors: `unknown-agent`, `invalid` (`state`, `errors`: no readable result object). Residual: the folders are opened when `promote` runs, not held from brief time; an agent that swaps its own folder for a link before `promote` is refused at the first link part, not earlier.

## fold

`fold --agent ID [--discard REASON]`: folds the agent's result into the ledger and `audit-run.json`. Refusals, nothing written, in this order: `unknown-agent`; `already-folded` (the brief is `folded` or `discarded`); `invalid` (`state`, `errors`: the `check` rules); `unpromoted` (`paths`: a local artifact `promote` did not copy); the kind fold (`collision`); `ledger-invalid`. Then the brief is `folded` with its fold order.

- Hunter: each unit takes the disposition as status, `checks` as `local_checks`, `reviewed_paths`, `candidate_fingerprints` as `result_fingerprints`, `unresolved`, and the result's `hardening` as bookkeeping. Candidates are kept by fingerprint: the first body and hunter, later hunters listed. Each `uncovered` entry becomes a unit: refs the four labels (profile `quick`: subsystem `profile/quick/all-in-scope-subsystems`), `ordinary_attack_class_block` the attack class when it starts `ATTACK-CLASSES.md#`, else null and the attack class joins `selected_companion_blocks`; `planned`; profile `quick`: `deferred`, `unresolved` `["quick_profile_final_critic"]`; no starting path in scope: `out_of_scope`, `unresolved` its reason plus `outside the run scope`. A known id with the same paths and blocks: in `duplicates`; with others: `collision`. JSON `agent`, `kind`, `units`, `candidates` (new fingerprints), `added`, `duplicates`.
- `--discard REASON`: the brief is `discarded`; a hunter's units it still owns go back to `planned`, no owner, no evidence; a verifier's carried units the same; a verifier's candidate stays without a final record. JSON `agent`, `discarded`, `units`.
- Critic: each `missing_units` entry becomes a unit as an `uncovered` one. Each `reassign_ids` unit: its live state (`wave`, `status`, `agent_id`, `reviewed_paths`, `local_checks`, `result_fingerprints`, `unresolved`) is appended to `attempts` with the `notes` text as `reassignment_reason`; `wave` plus 1, `planned`, no owner, no evidence. Profile `quick`: added and reassigned units are `deferred`, `unresolved` `["quick_profile_final_critic"]`. Each `resolved_prior_leads` fingerprint joins `resolved_prior_leads` of every unit it links (prior or current), its note in `resolved_prior_lead_reasons`. JSON `agent`, `kind`, `added`, `duplicates`, `reassigned`, `resolved`, `stop` (the result's).
- Verifier: the record becomes the final record of its fingerprint. A carried unit the verifier holds becomes `candidate`, owner the verifier, `result_fingerprints` the fingerprint, the verifier checks as `local_checks`; every other unit linked to the fingerprint gets the checks too. A record with another fingerprint replaces the old one in the links: JSON `fingerprint_changed` `{from, to}` (else null). JSON `agent`, `kind`, `fingerprint`, `verdict`, `units`.
- Recheck: the decision joins the recheck verdicts of the fingerprint; `replace`: the record replaces the final record, JSON `diff` the keys whose values changed; optional `checks` join the linked units. JSON `agent`, `kind`, `fingerprint`, `decision`, `diff`.

## findings

`findings [--incomplete REASON]`: writes `findings.json` (the final records, sorted by fingerprint), runs `validate-findings.cjs` on it and `validate-coverage-ledger.cjs` on the ledger, then sets `run-metadata.json` `run_status`. `complete` only when nothing is open: no `open` brief, no `planned` or `in_progress` unit, a final record for every candidate fingerprint (hunter candidates, and the prior fingerprints of in-scope verifier-owned carried units), and in profiles `standard` and `deep` a `verified` last recheck of every final `confirmed` and `needs_validation` record and a last folded critic that is `--final`, added no `planned` unit and reassigned none; profile `quick`: one folded critic. JSON `run_status`, `records` (count), `open`. `--incomplete REASON`: every `planned` unit `deferred` with the reason; `run_status: incomplete`, `incomplete_reason`; `release-record` then gives `run-incomplete`. Errors: `open` (exit 1, `run_status` unchanged, `records`, `open`: `[{kind: brief|unit|candidate|recheck|critic, ...}]`; `findings.json` is still written), `invalid-run` (`tail`: a validator failed; `run_status` unchanged).

## status

`status`: JSON `run_status`, `briefs` (`[{agent, kind, state, errors}]` in id order; `state` `folded` or `discarded`, else the `check` state `missing`, `invalid` (with `errors`) or `ready`), `units` (count per status), `counts` (briefs per kind). Writes nothing. The parent calls it after each agent notification.

## report

`report --summary FILE`: writes `REPORT.md`, `FINDINGS-DETAIL.md` and `NEEDS-VALIDATION.md` into the run folder, each by temp file and rename, from `findings.json`, the ledger, `run-metadata.json`, the trusted state and the summary file. Every value from a record, a unit or a note is put on one line (`release.one_line`; a non-string as sorted JSON), and a record title only ever follows `### Finding <n>: ` or `### Needs validation <n>: ` (`n` from 1 in fingerprint order), so no title forges a heading. `REPORT.md`: `# <run_id> security audit report`, then `## Run` (run id, profile, scope, budget, source commit, `run_status`, `incomplete_reason` when set, `execution_policy`, prior runs, `deferred` and `out_of_scope` counts, carried same-source and changed-source unit ids), `## Security posture` (the summary file, verbatim), `## Confirmed findings`, `## Confirmed finding details`, `## Needs validation`, `## Hardening notes` (one `- ` bullet per unique ledger `hardening` note, sorted, nothing else: `release-record` counts them), `## Coverage` (units per status, each `deferred` and `out_of_scope` id with its `unresolved`, the last critic). `FINDINGS-DETAIL.md`: the details of each confirmed record of severity `medium`, `high` or `critical`. `NEEDS-VALIDATION.md`: each `needs_validation` record. JSON `files` (the 3 paths). Errors: `not-closed` (`run_status` not `complete` or `incomplete`: run `findings` first), `no-summary` (the summary file is unreadable).
