# board

- `board [--repo <path>] [--event session-start|prompt|stop|subagent-start|subagent-stop|post-tool] [--claim <slug>] [--no-serve] [--stop-server]`: writes status notes to `<notes>/Dev Loop Board/Features/` (own notes in `Dev Loop Board/` move there, also an own name that does not parse; a `dev-loop-board/` folder is never read or moved by the writer; the server reads both spellings of the folder and of `Features`, each folder once by device and inode), `Dev Loop Board/Dev Loop Board.md` (Dataview), and starts the server (127.0.0.1, port 7777 or `DEVLOOP_BOARD_PORT`). `--event` reads hook JSON (`cwd`, `session_id`, `agent_id`) on stdin. Claude `subagent-start` (from `gate-snapshot.sh`) and `subagent-stop` track the session's running subagents: keyed by `agent_id` with the hook's `transcript_path` (a `subagent-stop` without `agent_id` changes nothing): a `stop` while one runs (its subagent transcript, or its start, changed under 30 min ago) sets no waiting; `session-start` keeps them. `--claim`: slug must match a spec in `<notes>/Features/`, else exit 1. A note is written only on a change: `updated` is the last real change, `notes` lists every own write-set note, written or unchanged. A Track S note (no spec) at Stage 6 or 7 stores `head` (the worktree HEAD); once its branch is gone, it is shipped when `git cherry origin/main <head>` has no `+` line. Shipped notes kept per project and machine: `board.shipped_kept` of `dev-loop.json` on the main ref (a whole number of 0 or more, else 5), the latest `shipped_at` first; each written note carries it as `shipped_kept` (a shipped note only in the write that ships it: a shipped note is never rewritten; a note pruned in that run is never written), and the page shows per project as many shipped rows as the `shipped_kept` of its most recently updated active note that has one, else of its most recently updated shipped note that has one, else 5. The page shows each title in Title Case (the first letter of each word upper case, every other character kept); a title equal to the `feature` slug, or empty, shows the slug with each `-` as a space. Server log `~/.config/dev-loop/board.log` (opened for append with no link follow, mode 0600, a regular file this user owns, else the server output goes nowhere and a start error says the log was refused instead of naming it; over 64 KiB it moves to `board.log.1` at launch). Server pidfile `~/.config/dev-loop/board-server.<port>.pid`: a `/health` pid that differs from it gives `port-busy`, no signal sent. Test only: `DEVLOOP_TEST_CLAIM_WAIT` shortens the claim wait. JSON `notes`, `removed`, `board_note`, `skipped` (`feature`, `reason`), `server` (`state`, `url`, `message`). Exit 0 also on skip or server error. Exit 1 with `error`: notes path unresolved, `--claim` unknown slug, `--claim` while the lock stays busy 10 s, any caught exception (saved best effort as `last_run` skip `error` with `message` `<Type>: <text>`). Exit 2 usage. `server.state`: `started`, `restarted`, `running`, `stopped`, `disabled`, `port-busy`, `stalled`, `error`. `--no-serve`, or a whole-run skip `no-dev-loop` or `notes-in-repo`: `disabled`. Whole-run skip `reason`: `no-dev-loop`, `stage-0`, `placeholder` (iCloud placeholder `.Spec.md.icloud` in a `Features/` folder, or in `specs/` while it exists; seen after a write: no catch-up pass, queue kept), `notes-in-repo`, `busy` (lock held, no `--claim`), `link` (`Dev Loop Board` or `Dev Loop Board/Features` is a symlink), `state-link` (`<git-common-dir>/dev-loop/` or one of its state files is a symlink), `state-owner` (that folder is not a folder this user owns; neither state skip saves `last_run`), `error` (`last_run` only); per feature: `rebase`, `link`, `placeholder`, `foreign`. Every busy run appends a line to `<git-common-dir>/dev-loop/board-events.jsonl` (`event` may be null), the lock holder applies it and runs catch-up passes that re-read git, worktrees, specs and claims. State files in `<git-common-dir>/dev-loop/`: `board.lock`, `board-claims.json`, `board-features.json`, `board-state.json` (features, sessions, last_run), `board-events.jsonl`; the folder is opened once with `O_NOFOLLOW` (an owner check) and every state file is read, written, renamed and deleted relative to that descriptor, so a folder swapped for a link mid-run redirects nothing; each JSON file is written through an exclusive temp file and a rename and read with no link follow (a linked file reads as missing); lock and queue are opened with `O_NOFOLLOW` and `O_NONBLOCK` and must be regular files: a FIFO or link at the lock gives skip `state-link`, at the queue it is dropped unread (a busy run queues nothing); any other read error of the queue is raised. A linked `Features/<x>/Spec.md` or `Plan.md`, a linked `Features/<x>` folder, a linked old-layout `specs/` or `plans/` folder or a linked file in them: not read, no spec or plan, in the board run only (`decide`, `status` and the other commands still follow a linked spec). `--stop-server`: stop, write nothing. Stage 2 runs `--claim`; hooks run `--event`.
