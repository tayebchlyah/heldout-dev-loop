# release-plan

- `release-plan [--repo <path>] [--harness claude|codex] [--profile quick|standard|deep] [--budget <n>] [--require-sandbox]`: run in the main worktree at the commit to audit. JSON `run` (`Run <N>`), `output` (created), `head`, `first` (no current record), `profile` (`quick` first, else `standard`), `budget` (100 first, else null), `scope` (`whole`, or `<base>..<head>`), `base` (null when first; the record sha when an ancestor of `HEAD`, else the merge base, none: null and `whole`), `exclude` (sorted paths out of the audit scope: the kit copies of an upgrade; `[]` unless `base` is the record sha, the tree at `base` holds the kit source (rule (d) of `reference/cli/ci-skip.md`) and the `.dev-loop/MANIFEST.json` `version` at `base` differs from the one at `HEAD`; then each MANIFEST `files` key under a kit root (`.agents/skills/`, `.claude/agents/`, `.claude/skills/`, `.codex/agents/`, `.codex/rules/`, `.dev-loop/hooks/`) whose `HEAD` tree entry and git mode equal the kit reference of `base` (`sha256:<hex>`: a regular file of that SHA-256; `link:<target>`: a symlink to that target; hook mode `100755`), plus the MANIFEST when its `files` equal the reference entries, changed in `<base>..<head>`, where every commit of `git rev-list <base>..<head> -- <path>` has a MANIFEST `version` that differs from the one at its first parent, both non-empty strings (a later hand edit, a missing or unreadable MANIFEST on either side, or a root commit keeps the path in scope); never a deleted copy, `dev-loop.json` or a merged config file), `prior_runs`, `sandbox` (`engine`, `images`, `runner`), `skill`. Exit 1 with `error`, nothing created: `dirty` (`paths`), `placeholder` (`files`, an iCloud placeholder under `$NOTES/Security Audit/`), `run-folder-exists`, `no-project-note`, notes path unresolved, `cannot read <note>: <ExcType>`, `git status failed`, `cannot resolve HEAD`, `old-notes-layout` (`$NOTES/security-audit` exists; `fix`: `devloop.py notes-migrate`).
- `--require-sandbox`: after every other check, before the run folder, exit 1 `{"error": "no-sandbox", "reason": "no-images"|"no-engine"}`, nothing created: `no-images` when `security_audit.images` of `dev-loop.json` at the repo top is not an object with a key, else `no-engine` when `docker info` fails. Without it: no check, `sandbox` as above. `/release-audit` passes it unless its arguments hold `--no-sandbox`.
