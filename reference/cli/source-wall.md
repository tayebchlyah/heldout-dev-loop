# source-wall

- `source-wall [--repo <path>]`: stdin one PreToolUse hook JSON object of a spec-tester call (Claude or Codex: `tool_name`, `tool_input`, `cwd`). `--repo` default: the cwd. Reads `source_dirs` from `dev-loop.json` at the main ref of that repo (`refs/remotes/origin/main`, else `refs/heads/main`), never the checkout file. The caller checks the agent.
- Output, exit 0: `{"mode": "configured"|"default", "deny": bool, "reason": string|null, "ref": "origin/main"|"main"|null}`. `default`: no main ref, no `dev-loop.json` there, or no `source_dirs` key; `deny` false. `configured` with `[]`: `deny` false. Deny reason: `Blocked: <entry> is outside this agent's territory (source_dirs).`
- Exit 1: `{"error": <message>}`. The main ref file is not a JSON object (`dev-loop.json at <ref> is not a JSON object: source_dirs cannot be read`), or `source_dirs` is invalid there (`source_dirs at <ref> is invalid: <rule>`). Hook input not a JSON object: `source-wall: hook input is not a JSON object`. A path text the OS cannot take (a NUL byte): `source-wall: <the error>`. Exit 2: usage error.
- Match (D1): an entry matches a repo-relative path that starts with the entry, or equals it without the final `/`; NFC, case-folded. The validator and the matcher live in `source_dirs.py`.

## Decision, configured key

1. Tops: each `worktree <path>` of `git -C <repo> worktree list --porcelain`, a bare entry skipped. Variants of each top: as listed, its `realpath`, and the `/private` twin of each (a leading `/private` added or stripped); folded. A form belongs to the longest variant `v` it equals or that it starts with plus `/` (the deepest top); its repo-relative path is the rest, `""` for the top itself. A form outside every top matches no entry.
2. Start folder: the payload `cwd` when a non-empty string, else the absolute `--repo`.
3. Seal exception, Bash or Monitor `command` only: the raw text holds no newline, no `$` and no backtick; its shell tokens (step 4) parse and none is an operator token (`; & | < > ( )` outside quotes; inside a quoted word they are text, so `--message "✅(acceptance) #302: Add tests"` keeps the exception); tokens: at least 3, the first `python3`, the second (joined to the start folder, `realpath`) equal to `<top realpath>/.agents/skills/dev-loop/scripts/devloop.py` of a top, folded, the third `seal`. Then `deny` false for the whole call.
4. Candidates, each a text with a folder:
   - `apply_patch`, or `Edit` / `Write` with a string `command` or `patch` and no `file_path`: the path of each `*** Add File:`, `*** Update File:`, `*** Delete File:` and `*** Move to:` line, trailing white space stripped. Nothing else; a patch body is no candidate.
   - `skillsread`: every string at any depth of `tool_input`.
   - Any other tool: the strings at any depth of `file_path`, `path`, `notebook_path`, `glob` (one starting with `!` dropped), `paths`, `files`, `url`, `source`, `destination`, `directory`, `filePath`, `uri`, `args`, and `pattern` except for `Grep`; a `file://` value also as its path (`file://` and a following `localhost` dropped); `path/glob`, and `path/pattern` except for `Grep`.
   - Bash or Monitor `command`, in addition: each backslash-newline pair removed (line continuation), heredoc bodies removed (the `search-wall` heredoc rule), then shell tokens: POSIX words with the operators `( ) ; < > | &` (runs such as `&&`, `||`, `>&`) and newline as tokens of their own (`shlex` with punctuation characters, no comments). On a parse error: the whitespace words. Every word, on both paths, is also taken again with all `'`, `"` and `\` removed, its parts and pieces below included, with the same folders (so `in""ternal` or `in\ternal` names `internal` in a command with an open quote, and inside a nested shell at any depth: `bash -c 'cat in""ternal/x.go'`, `bash -c 'cd int""ernal; cat x.go'`). Folder moves: the leading run of the command, when it parsed, is a chain of `cd` or `pushd` commands, each the token `cd` or `pushd`, one target token, then `&&`, `;`, newline or the end. A target that is not an operator, does not start with `-` or `~` after expansion (step 5), holds no unresolved character, and joined to the current folder and normalized names an existing folder, moves the folder: the words after it are checked at that folder only, not the start folder (`cd tests/acceptance && python3 -m pytest api/test_gizmo.py` with an `api/` entry, `cd <top> && python3 -m pytest tests/acceptance` with a `tests/` entry: open). With `CDPATH` set, a relative target that does not start with `./`, `../`, or equal `.` or `..`, does not move. The run ends at the first command that is not such a `cd`: a cd that may not run, may fail or runs in a subshell (after another command, after `|`, `&`, `||`, `(`, in a compound command, with an option, a second argument or a redirect, a missing folder) never moves. Every other `cd` or `pushd` (each such later or failed one, and on a parse error) keeps today's rule: words starting with `-` (except `-` itself) are passed over and the next word is a new folder, joined to the last one and normalized (on a parse error, the word with its quotes removed). A target that is `-`, empty, starts with `~` or `-` after expansion, unresolved, relative to an unknown folder, or that holds any of `; & | < > ( )` is the unknown folder. Such a `cd` adds the unknown folder for the words after it, and every folder seen so far (the start folder and each move): after its target, and right after a word with a part exactly `cd` or `pushd`, the parts of the word as below, the white space and quote split and the quote-stripped word included (`true&&cd`, `eval 'cd docs'`, `bash -c 'cd docs; ...'`). So a later relative word also gets the unresolved text match; the `cd` target itself does not. Each word gives: itself, each part after a split at `: = < > | ; & ( )`, each piece of these after a split at white space, `'`, `"` and a backtick; empty strings dropped.
   Field texts take the start folder. A command word takes the folders of the rule above: the last move in the leading run, else every folder seen so far, the unknown folder included. It is checked once per folder (steps 5 to 7), and the first deny wins: a word after `echo cd /`, `false && cd /tmp;` or `cd /tmp ; cd -` is still checked at the start folder.
5. Expansion: a leading `~+` or `~+/` from the candidate's folder; a leading `~` or `~/`, `$HOME` (not followed by a name character) and `${HOME}` from `HOME` when set; `$PWD` and `${PWD}` from the candidate's folder.
6. Unresolved text: after expansion it holds `$`, a backtick, `*`, `?`, `[` or `{`, it still starts with `~` (`~-`, `~user`), or it is relative with an unknown folder. Suite glob, skipped like a resolved suite path: the folder part before the first unresolved character (text up to its last `/` before it), joined to the folder, resolves to `tests/acceptance` of its top or under it, the text holds no `..` and no leading `~`, the rest holds no `$`, backtick, `[`, `{` and no segment that starts with `.`, and no symlink under that folder resolves out of the suite (`tests/acceptance/**/*.py` with a `tests/` entry: open). Else matched as text: an absolute text under a top (any variant) by its repo-relative remainder only, so the checkout path never matches (a repo under `/home/u/src/`, a worktree under `.claude/worktrees/`); any other text as is. The first entry whose folded name without the final `/` stands in the folded text as whole segments (before it: start or a character outside `a-z 0-9 _ . -`; after it: `/`, a quote, a backtick, `; | & ) < > * { } , $`, white space or the end) denies.
7. Resolved text: the absolute path (the text, or the folder plus `/` plus the text). Normalized form: `normpath`, a leading `//` collapsed to `/`; resolved form: `realpath` (symlinks, the deepest existing part). The resolved form at `tests/acceptance` of its top, or under it: the candidate is skipped (D3). Else the first entry that matches the repo-relative path of either form denies. A text with a `..` path segment also gets the text match of step 6 (remainder rule included) (a `..` that climbs out of a folder changed by `bash -c 'cd docs; ...'`, `tar -C docs` or `os.chdir`).

## Exceptions and limits

- D3: the held-out suite folder by its resolved form, so a symlink inside it that points out does not pass; the lone seal command.
- A bare word equal to a walled folder at the current folder is denied (`pytest -k api` with `api/`): the reason names the folder.
- Gaps (spec Non-goals): a variable or wildcard that hides the entry name itself (`d=internal; cat $d/x.go`, `cat int*/x.go`); quoting or substitution that starts with `$` or a backtick inside a name (`cat in$'t'ernal/x.go`, `cat in$()ternal/x.go`), the same class; a path in a heredoc body; a recursive search from a folder above a source folder; git commands that print source with no path word (`git log -p`, `git show <sha>`, `git diff <rev> <rev>`); a copy of source outside the repo (the Codex kit copies under `~/.codex/dev-loop/kit/`); source served over a URL; files at the repo root; a local move of the main ref; a shell edit of a hook script or of the kit CLI (`seal-check` reports `kit-changed`). A folder change with no `cd` (`git -C`, `tar -C`, `os.chdir`) followed by a relative path with no `..` segment is not tracked. On a parse error, `cd <dir>;cmd` with no space stays one word, so `<dir>;cmd` is no folder (the unknown folder covers the later words). The taint audit stays the backup.

## Callers

- The spec-tester branch of `deny-acceptance-to-subagents.sh`, the `spec_tester` branch of `acceptance-wall.sh` and `deny-path.sh --source-dirs`, each only when the main ref has the key. They run the `devloop.py` of the kit copy that holds the hook. `deny` true: exit 2 with `reason`; `mode` `default`: the four-folder match `src/ app/ backend/ frontend/`. No CLI, a non-zero exit or output with no boolean `deny`: a deny naming `source_dirs` for a tool that names a path or a command.
