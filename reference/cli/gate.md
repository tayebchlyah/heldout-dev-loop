# gate

- `gate --summary`: `commands.gate`, else `scripts/gate.sh`. JSON `exit`, `log`, `seconds`, `failures` (each failed or errored JUnit case as `FAILED <classname>::<name>`, prefixed `<file>::` when the case has a `file` attribute (the path relative to the repo top when under it, else as given), read per report; `FAILED <report>.xml: report does not parse` per broken report; `FAILED <report>.xml: report missing` per report the previous gate run of the worktree (newest other `gate-*-reports` folder with an XML) wrote and this run did not, only when the project gate failed (a green run that writes fewer reports lists none), none on a first run; each log line that starts with `FAILED `, `ERROR ` or `--- FAIL`, or holds ` FAIL `, added after the JUnit cases when no JUnit case failed or a report does not parse or is missing), `slowest` (JUnit XML in `DEVLOOP_REPORT_DIR`, else `[]` and `hint`), `seal` (the `seal-check --uncommitted` payload; the process exits 1 when `seal.ok` is false, even if the project gate passed; the JSON `exit` stays the project gate's own exit), `weakened` (list of `{path, reason}`, `reason` `skip-added` or `assertions-removed`, for test files in `git diff <base>`; report only, never changes the exit code), `size` (the `size-check --uncommitted` payload; the process exits 1 when `size.ok` is false), `ratchet` (time ratchet, `skill/scripts/ratchet.py`; the process exits 1 when `ratchet.ok` is false, the JSON `exit` unchanged). Shape: `ok`, `state` (`checked`, `no-baseline`, `skipped`, `error`), `reason` (`off`, `no-junit`, `no-main-ref`, the error text, else null), `baseline` (`{tree, head, at}` of the record used, or null), `factor`, `red` (`[{id, seconds, baseline, rule, limit}]`, `rule` `unmarked`, `marked` or `max`), `attention` (`[{id, seconds, rule, limit}]`), `waived` (`[]` for the gate), `growth` (`{share, limit, ok, waived}` or null), `record`. Order: no `<main-ref>` (`refs/remotes/origin/main`, else `refs/heads/main`): `skipped` `no-main-ref`; then `test_time` of `dev-loop.json` at `<main-ref>` (absent or not parsing: the defaults `{"gate": {"unmarked": 2, "marked": 10, "max": 30, "growth": 0.03}, "acceptance": {"unmarked": 10, "marked": 30, "max": 60}}`, a missing key takes its default): `false`: `skipped` `off`; not an object, an unknown key, or a value that is not a finite positive number (a bool too): `error`, `ok` false, `reason` names the key; no executed JUnit case: `skipped` `no-junit`. Test id: as in `failures`; time: the case `time`, 0 when missing or not a number; a skipped case is not read; an id in two reports keeps the larger time. Baseline: the record `<git common dir>/dev-loop/test-times/gate/<tree>.json` of the first tree of `git log --first-parent -n 200 $(git merge-base HEAD <main-ref>)` that has one; a record that does not parse is passed over. None: `no-baseline`, `ok` true, `red` empty, `attention` each test over `max` (raw time), `factor`, `baseline` and `growth` null. Load factor: the median of branch time / baseline time over the ids of both runs with a baseline time of 0.1 s or more, 1 when fewer than 10, never under 1; each time is divided by it. Slow mark: the word `slow` in the id, case ignored, no letter before or after it. Red: a new id over `max` (rule `max`), else over `marked` with the mark or `unmarked` without it; a known id grown (at least 1.5 times its baseline and 5 s more) and over `max`. Over is strict. `seconds` and `baseline` rounded to 0.1, items sorted by id. Growth: `share` = (sum of branch times - sum of baseline times) / sum of baseline times (0 when that sum is 0), rounded to 3 decimals; `ok` compares the unrounded share with `limit`. Waiver: a commit of `<main-ref>..HEAD` with a `Test-Time: <reason>` trailer: `growth.waived` is the newest reason when `growth.ok` is false, and `ratchet.ok` stays true; it never waives a red item. Record: when the process exits 0, `GATE_SCOPE` is not `changed`, `state` is `checked` or `no-baseline`, and `git status --porcelain` is empty, the run writes `<git common dir>/dev-loop/test-times/gate/<HEAD tree>.json` (`tree`, `head`, `at` in UTC, `times`: seconds per id divided by the run's load factor, 1 on `no-baseline`), replacing a record of the same tree, then keeps the newest 50 records of the folder (by modification time) and removes the rest; `record` is its path, else null. A rebase merge keeps the tree, so the Stage 7 gate record becomes the record of `main`.
