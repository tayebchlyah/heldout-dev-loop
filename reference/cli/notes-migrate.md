# notes-migrate

- `notes-migrate [--repo <path>] [--apply [--plan <hash>]]`: moves an old notes layout (`specs/`, `plans/`, `framing/`, `answers/`, `maps/`, `security-audit/`, `dev-loop-board/`) to the new one (`Features/<YYYYMMDD> <Title>/` with `Spec.md`, `Plan.md`, `Framing.md`; `Answers/`, `Maps/<Effort Title>/`, `Security Audit/Run <N>/`, `Dev Loop Board/Features/`), and rewrites the links to the moved notes, the frontmatter of the feature notes and the audit run ids. It computes the whole plan first: every move, and the full new text of every note it changes. `plan_hash`: sha256 of the moves and the old and new sha256 of each changed note. Without `--apply` it changes nothing. `--apply` needs the `--plan` of a dry run; a plan computed again with another hash: exit 1, `plan-changed`, nothing changed.
- Refuses a notes folder inside a worktree or the git dir of the repo (`notes-in-repo`, the `board` rule). Kit version for the `old-kit-worktree` guard: `version` of `<repo>/.dev-loop/MANIFEST.json`, else `0`.
- JSON keys, in this order: `applied` (bool), `plan_hash`, `moves` (`{from, to}`, relative to `$NOTES`; a board note removed: `to` equals `from`), `frontmatter` (relative paths it changes), `links` (`{files, count}`), `audit_ids` (ids rewritten), `outside_links` (`{file, line, link}`: a vault note outside `$NOTES` linking a moved path, never changed), `outside_skipped` (vault files it could not read: placeholders, unreadable files), `repo_links` (`{file, line}`: tracked repo files outside `tests/acceptance/` naming an old path, never changed), `git_case` (commands, run from `$NOTES`, that make a `core.ignorecase` git index follow each case-only folder rename), `gitignore` (new folder names, or `Security Audit/Run <N>/` run folders, the vault git repo must also ignore), `ambiguous` (plan or framing notes that match two specs), `blocked` (`{path, reason}`), `log` (the log note, relative to `$NOTES`, or null), `error` (null or a code). With an `error`, also `message`: what happened and the fix.
- Exit 0: no `blocked` item, no `error`. Exit 1: `blocked` items (nothing changed: `target-exists`, `link`, `placeholder`, `unreadable`, `bad-name`, `no-date`, `collision`, `unknown-entry`, `old-kit-worktree`, `open-ledger`, `gitignore`), or `error`: `notes-path`, `notes-in-repo`, `plan-changed`, `locked`, `io`. Exit 2: usage, or `--apply` with no `--plan` and no journal. Already the new layout, no journal: exit 0, every list empty, no log.

## Apply, journal and log

- `--apply` takes `$NOTES/.notes-migrate.lock` (exclusive create, `{"host", "pid"}`; a lock of this host whose pid is not running is stale and removed), then writes `$NOTES/.notes-migrate.json` (host, `plan_hash`, each step with the sha256 it expects before and after, each new note text, the report) before the first change.
- Order: folder renames, feature moves, note writes. A move never overwrites: its target must not exist. A rename that changes only the case goes through `<name>.notes-migrate-tmp` in the same parent. The note writes hold the `decide` lock (`<git-common-dir>/dev-loop/decide.lock`). Emptied old folders are removed with their `.DS_Store`.
- At the end, when the run changed a file: `$NOTES/<YYYYMMDD> Notes Migration.md` (`Notes Migration 2.md` and so on on the same day; `type: note`) lists each move, each `outside_links`, `repo_links` and `git_case` item: the record for a manual undo (no automatic undo: the vault git history or iCloud) and the follow-up. Then the journal and the lock are removed.

## Recovery

- A run that finds the journal resumes it: it runs the journal's plan, not a new one, needs no `--plan` (a `--plan` other than the journal's: `plan-changed`), and skips the guards. Each step is idempotent: a move whose source is gone and whose target has the expected sha256 is done; a note whose file already has the new sha256 is done.
- `io` (the journal stays): a file with neither sha256, or a target that synced in after the plan. Restore the planned text (or move the target away) and run `--apply` again, or delete `.notes-migrate.json` and start a new dry run.
- `locked`: a live lock, or a journal or lock of another host. The message names the host. Run `notes-migrate --apply` on that host, or delete the lock and the journal after checking that host is idle.
- A dry run with a journal present prints the journal's report.

## Stage 0

The `check_setup.py` `old-notes-layout` line belongs to Stage 0. Every machine that shares the notes folder upgrades the kit first. Stage 0 runs `notes-migrate` (dry run) and shows the user `moves`, `outside_links`, `repo_links`, `git_case`, `gitignore` and `blocked`. It runs `notes-migrate --apply --plan <plan_hash>` only after the user confirms. Delivery never runs `notes-migrate`: it moves user files. After `--apply`, the agent fixes each `outside_links` and `repo_links` item only after the user confirms it, and gives the user the `git_case` commands to run from `$NOTES` (the kit never runs a git write in the notes repo).
