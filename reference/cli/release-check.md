# release-check

- `release-check [--repo <path>] [--no-build] (--tag <name> | --sha <rev>)`: may a commit get a release tag. Release tag: `v*` (`fnmatchcase`); another `--tag` name: `ok` true, `skipped` `not-a-release-tag`. Target: `<tag>^{commit}`, or `--sha`. Project note: `$NOTES/Project Note.md`, else `$NOTES/<notes folder name>.md`. Reasons, in order: `no-audit` (no current record, the last `## Release audits` bullet `- <date> Run <N> at <sha>: confirmed <n>, needs validation <n>, hardening <n>, profile <p>, scope <s>`), `record-mismatch` (`detail`: run folder `$NOTES/Security Audit/Run <N>/run-metadata.json` missing, unparsed, `source_ref.commit` other than the record sha, or `run_status` not `complete`), `stale-audit` (`paths`: the record sha is not the target, and not an ancestor whose diff to the target has only test or doc paths and the paths `ci-skip` allows, see Release commit), `open-security` (`items`: a `## Deferred` top-level bullet `<date> (security, confirmed|needs-validation, <Run N or slug>): <text>`; open until a sub-bullet `- Ruling <date>: accept|close <reason>` closes it; `fix #<n> <reason>` or a ruling word with no reason keeps it open), `unparsed-security` (`lines`: a bullet with the word `security` that does not match: fails closed). JSON `ok`, `tag`, `target`, `record`, `wave`, `wave_ignored`, `reasons`. Exit 0 when `ok`, else 1. Exit 1 with `error`, no `ok`: no repo, tag or rev unresolved, notes path unresolved, `no-project-note`, `cannot read <note>: <ExcType>`. While `$NOTES/security-audit` exists (the old layout): exit 1, `{"error": "old-notes-layout", "fix": "devloop.py notes-migrate"}`. Exit 2 usage. The git guards run it with `--no-build` on a `v*` tag push and `gh release create`.

Release commit: when the record sha is an ancestor of the target, a changed path that is not a test or doc path still leaves the audit current if `ci-skip` allows it (`CHANGELOG.md`, a version-only change of a `version_files` path, a `dev-loop.json` change of `version` only, the kit copies of a kit upgrade that equal the kit the record commit's own installer builds, so in a project without the kit source every kit path makes the audit stale; rules in `reference/cli/ci-skip.md`). A kit copy (under the kit roots) whose tree entry at the target equals the kit the record commit's own installer builds, a copy the target drops that the record MANIFEST `files` listed and that build no longer has, and a MANIFEST whose `files` equal that build, keep the audit current at any kit version, so also an `upgrade` again at the same version (#185); `ci-skip` keeps its version rule. The build runs that commit's `lib/kit.mjs` in `node`, from a folder under `<git common dir>/dev-loop/` (read-only to the Codex sandboxes; a caller denied a write there uses the temp root, any other error there gives no build). `--no-build`: no build, so no code of the repo runs (the git guards run on the host, #199): every kit copy, the MANIFEST and a kit upgrade commit are code paths, and the audit fails closed to `stale-audit`. Any other code path makes the audit stale, and `paths` lists every non-test, non-doc changed path. A bad `version_files` at the target fails closed to `stale-audit`.

Fix wave: W, the last `- <date> Run <N> fix wave at <sha>: #<a>, #<b>` bullet of `## Release audits` that names the current record's run (`release-record --fix-wave`, `reference/cli/release-record.md`). W is used when: W sha is a strict descendant of the record sha and an ancestor of the target or equal to it; the `--fix-wave` check of `<record sha>..<W sha>` with W's issues finds no foreign commit and no unfixed issue; no local `v*` tag that contains W sha (`git tag --list 'v*' --contains`) points at a commit other than the target (peeled). A tag at the target never ends the wave: the git guards run this on a tag push, after `git tag -a` made the tag. Used: `stale-audit` is measured from W sha instead of the record sha, same rules, and `wave` is its line. Else `wave` is null and `wave_ignored` gives why: `not-ancestor`, `foreign-commit`, `unfixed`, or `released: <tag>` (the first such tag in name order). `wave_ignored` is null when no wave line names the record's run; both are null with no record or a `record-mismatch`. `release-plan` keeps the record sha as its base, so the next audit covers the fix code.
