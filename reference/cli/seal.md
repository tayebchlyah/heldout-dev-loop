# seal

- `seal --feature <slug> --message <subject> [--reverts <sha> ...]`: commits the staged change under `tests/acceptance/`. Reads the index, stages nothing. Message: subject, `This reverts commit <sha>.` per `--reverts`, `Acceptance: <slug>`, `Dev-Loop-Seal: <value>` (valid when either seal trailer matches; sha256 of one `<path> <blob>` line per staged path, sorted, blob `deleted` for a removal), `Dev-Loop-Seal-Patch: <value>` (sha256 of the first field of `git patch-id --verbatim` of the `-U1` diff under `tests/acceptance/`: whitespace counts, line numbers do not, one context line on each side, so a clean rebase keeps it (git stops on a conflict when an upstream change touches a context line) and a sealed line moved to other neighbour lines gets a new value). After the commit hooks ran, recomputes both from the commit and amends (`--no-verify`) when they or the message differ. Then adds one entry to the seal record `<git-dir>/dev-loop/seals.json` (the worktree's own git dir; JSON `{"seals": [...]}`, oldest first, written under a lock, through a temp file and a rename): `branch` (full ref), `commit`, `patches` (the patch value), `seal`, `feature`, `paths`. A detached `HEAD`: no entry. `seal-check` reads it (`seal-dropped`). Exit 1 with `error` `seal record not written: <reason>` and `commit` (the sha): the commit is kept; recovery: fix the cause, `git reset --soft HEAD^`, `seal` again. Exit 1 with `error`: nothing staged under `tests/acceptance/`, a staged path outside it, slug not lower case words joined by `-`, a `--reverts` value that is not a commit. Exit 1 with `error` `git patch-id failed: <stderr or "no output">` (`patch-id` exits non-zero or prints no id: a git older than 2.39, a broken git), no commit. The same `error` after the commit hooks ran: exit 1 with `commit` (the sha), the commit kept with the value from before the commit, no amend; recovery: fix git, `git reset --soft HEAD^`, `seal` again. Exit 1 with `error` `file over the size limit` and `size` (the violations), no commit: a staged path under it over 40,000 bytes, new or grown against `<base>` (symlink, gitlink, binary skipped; no MANIFEST or exempt skip). Exit 2: both modes or neither. JSON `commit`, `seal`, `files`. Only `spec-tester` may run it (`git-guard.sh`).
- `seal --rebase-continue`: in a rebase, value from the index into the `Dev-Loop-Seal` trailer of the rebase commit message, and `Dev-Loop-Seal-Patch` (last paragraph only), then `git rebase --continue`, no editor. Exit 1 with `error`: no rebase, a staged path outside `tests/acceptance/`, nothing staged under it, "the stopped commit is not a seal commit" (no `Dev-Loop-Seal` trailer in its last paragraph), "nothing staged under the folder", "git rebase --continue failed" (the rebase ended without continuing), `git patch-id failed: <stderr or "no output">` (message not written, the rebase stays stopped). JSON `seal`, `files`, `rebase` (`continued`, or `stopped` with the next conflict and `conflicts`). After the continue, the seal record: each entry of the rebased branch that holds the old patch value of the stopped commit keeps it and gets the new value appended to `patches` (a reset to `ORIG_HEAD` stays present), with the new `commit`, `seal` and `paths`. No such entry: a new one (`patches` old and new, `feature` from the `Acceptance:` line). No record: none made. A failed write: exit 1, `error` `seal record not written: <reason>` and `commit`, the record unchanged.
