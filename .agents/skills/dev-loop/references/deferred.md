# Deferred triage

Read this file before you rule on a `## Deferred` item: the Stage 1 cap check, a release, any ruling the user asks for.

- Security item: never propose to keep it open, `accept` or `close` it on a reading alone when a live check is cheap. A cheap check is a script, test or command that calls the real code and shows the hole open or closed, in minutes. Run it first, quote its output under the item, then propose the ruling. No cheap check: say so, and name the check that would settle it.
- A fix that rests on a CLI flag: quote the line of the CLI's own `--help` (or its docs) that says what the flag does, never a summary of it.
- Ruling form: `  - Ruling <date>: <word> <reason>`, exactly two spaces or a tab before `-`. Words: `fix #<n>`, `accept`, `close`, and `waive <tag> <reason>` for one release only: closed for `release-check` of that tag (`--tag <tag>` or `--sha <rev> --for <tag>`), open for every other tag and wherever no tag is given (`release-record` skips a re-find, the Deferred cap, `/garden`). Never an `accept` or `close` "for rc.N only": `release-check` fails it as `unparsed-security`.
- Quote check output under an item in a fenced block (three backticks or tildes, closed before the next item): lines inside a fence are never rulings. The fence closes on a bare line of the same character, at least as long as the opener; an info string does not close it. An unclosed fence fails `unparsed-security`.
- Keep every line of an item indented, or in a fence. A line at column 0 that is not a `- ` bullet (text, a heading, a `*` or `+` bullet) does not end the item: each ruling line after it fails `unparsed-security`. Only the next `- ` bullet at column 0 ends the item. Write each item as `- ` at column 0: a `*` or `+` bullet, or one space before the marker, that names security fails `unparsed-security`.
