# AGENTS.md

## Purpose

dev-loop: stage-driven development loop skill for Claude Code and Codex, plus its installer. Tracks S, M, L. Session A: Stages 1 and 2, stops at spec approval. Session B: Stages 3 to 7 chained under the autonomy grant. Track S: no spec, no plan. `devloop.py status` detects the stage.

## Repo map

Dogfood: this repo runs dev-loop on itself, installed kit pinned to a release (`dev-loop.json` `version`). Never edit installed kit (`.agents/skills/dev-loop/`, `.agents/skills/pause/`, `.agents/skills/continue/`, `.claude/agents/`, `.claude/skills/dev-loop`, `.claude/skills/pause`, `.claude/skills/continue`, `.codex/agents/`, `.codex/rules/`, `.dev-loop/`): changes only by `upgrade` to the next tag, after each release. ## devloop CLI

`python3 .agents/skills/dev-loop/scripts/devloop.py <command>`. One JSON object on stdout. Exit 0 success, 1 failure the JSON describes, 2 usage error.

- `status [--repo <path>] [--feature <slug>]`: `stage` (0 to 7, `shipped`, or `rebase` while a rebase is in progress), `check`, `next`, `feature`, `track`, `worktree`. `--repo` defaults to `.`. Spec frontmatter `shipped: <YYYY-MM-DD>` non-empty: `shipped`, no git check, left out of `features` (Stage 7 writes it and `pr: <url>` after the merge; not `status`: the notes vault owns it). No `--feature` on a branch without `/` (the default branch): Stage 1, plus `features`: each spec not shipped that is unapproved or has a local or origin branch `<prefix>/<slug>` or a worktree, with its `feature`, `stage`, `worktree`. An approved spec with neither is left out, stage not computed (`--feature <slug>` still resolves it). Track S: Stage 6 until `$(git rev-parse --git-dir)/dev-loop/review-done` exists. Spec frontmatter `acceptance: regression` or `none` (any case): no Stage 3 acceptance file needed, Stage 4 once the worktree exists. Stage 3 done: a file under `tests/acceptance/` named after the slug, or a commit in the history of `HEAD` that touches `tests/acceptance/` and has the message line `Acceptance: <slug>` (exact slug; a spec that only extends earlier files); no `origin/main` needed. An approved spec with no branch is `shipped` when `main` holds such a file, or `main` or `origin/main` holds such a commit. Optional `board` (`at`, `skipped`: the last board run skipped for a reason other than `busy`, `rebase`, `no-dev-loop`, `stage-0`, or crashed: `error`) and `kit_drift` (`worktree`, `main`: the worktree kit is newer than the main worktree's). Pause note: `<git-dir>/dev-loop/pause.json` of the worktree it reports on (the feature worktree, else the repo top level): `paused` (the note, `{"error": "unreadable pause note"}` when not a JSON object) and `next` `resume from the pause note`; a note with `reason` other than `manual` whose `session` is the current session (`CLAUDE_CODE_SESSION_ID`, else `CODEX_THREAD_ID`) is deleted instead, no field. On `main` without `--feature`, each `features` item whose worktree has a note gets `paused: true` (same rule). Only `status` deletes a note. Reads local state only, never fetches.
- `logged [--name <name>] -- <cmd>`: full output to `$(git rev-parse --git-dir)/dev-loop/logs/<name>-<timestamp>.log`. `<name>` defaults to the basename of the command. JSON `exit`, `log`, `seconds`, `tail`.
- `gate --summary`: `commands.gate`, else `scripts/gate.sh`. JSON `exit`, `log`, `seconds`, `failures`, `slowest` (JUnit XML in `DEVLOOP_REPORT_DIR`, else `[]` and `hint`), `seal` (the `seal-check --uncommitted` payload; the process exits 1 when `seal.ok` is false, even if the project gate passed; the JSON `exit` stays the project gate's own exit), `weakened` (list of `{path, reason}`, `reason` `skip-added` or `assertions-removed`, for test files in `git diff <base>`; report only, never changes the exit code).
- `seal --feature <slug> --message <subject> [--reverts <sha> ...]`: commits the staged change under `tests/acceptance/`. Reads the index, stages nothing. Message: subject, `This reverts commit <sha>.` per `--reverts`, `Acceptance: <slug>`, `Dev-Loop-Seal: <value>` (valid when either seal trailer matches; sha256 of one `<path> <blob>` line per staged path, sorted, blob `deleted` for a removal), `Dev-Loop-Seal-Patch: <value>` (sha256 of the `git patch-id --stable` of the `-U0` diff under `tests/acceptance/`). After the commit hooks ran, recomputes both from the commit and amends (`--no-verify`) when they or the message differ. Exit 1 with `error`: nothing staged under `tests/acceptance/`, a staged path outside it, slug not lower case words joined by `-`, a `--reverts` value that is not a commit. Exit 2: both modes or neither. JSON `commit`, `seal`, `files`. Only `spec-tester` may run it (`git-guard.sh`).
- `seal --rebase-continue`: in a rebase, value from the index into the `Dev-Loop-Seal` trailer of the rebase commit message, and `Dev-Loop-Seal-Patch` (last paragraph only), then `git rebase --continue`, no editor. Exit 1 with `error`: no rebase, a staged path outside `tests/acceptance/`, nothing staged under it, "the stopped commit is not a seal commit" (no `Dev-Loop-Seal` trailer in its last paragraph), "nothing staged under the folder", "git rebase --continue failed" (the rebase ended without continuing). JSON `seal`, `files`, `rebase` (`continued`, or `stopped` with the next conflict and `conflicts`).
- `seal-check [--uncommitted]`: checks the seal commits in `<base>..HEAD` (`<base>`: `git merge-base HEAD origin/main`, else `main`, else none: no commit checked). A seal commit is valid when its blob value or its patch value matches (a clean rebase keeps the patch). JSON `ok`, `violations` (`{reason, commit, path}`: `bad-seal`, `unsealed`, `taint-unreadable` (the taint file cannot be read; `path`), `kit-changed` (a path under `.agents/skills/dev-loop/` or `.dev-loop/`, or a `.dev-loop/MANIFEST.json` key at `<base>` or `HEAD`, differs from `<base>` and its content does not match the current MANIFEST entry (`sha256:` of the bytes, or `link:` target); fine: the MANIFEST itself, and a path gone from both the tree and the MANIFEST (an `upgrade` or `init` writes both); with `--uncommitted`, the working tree against `<base>`, untracked files under the two folders too, `__pycache__/` and `*.pyc` skipped; `seal.sh` adds a kit remedy), `changed-after-seal` (both with `commits`: the non-seal commits that touched the path), `uncommitted` only with `--uncommitted`: tracked changes, untracked paths only when named like a test file), `taint` (open records), `warnings` (closed records, audit skips). Exit 0 when `ok`, else 1; exit 2 outside a git repo.
- `verify-init --base-url <url> [--name <skill>]`: writes `.agents/skills/<skill>/SKILL.md` (frontmatter `name`, H2s `Launch`, `Doctor`, `Drive`, `Evidence`, `Cleanup`), `features/README.md`, the link `.claude/skills/<skill>` to `../../.agents/skills/<skill>` (`claude` in `harnesses`), and `verify` `{skill, base_url}` last in `dev-loop.json` (2-space indent). `<skill>` default `verify-<main worktree basename>`, lower case, runs of other than `a-z0-9` to `-`. Each part to fill holds `<!-- dev-loop: fill -->`. JSON `skill`, `files`, `config`. Exit 1 with `error`, nothing written: no `dev-loop.json`, `verify` present, skill folder or link present, bad name, URL not `http(s)://`. Exit 2 usage.
- `drive [--all | --since <sha> | --routes-from <file>]`: `verify` absent or `false`: `{"ok": true, "skipped": "no-verify", "routes": []}`. Selects each map entry whose `paths` match `git diff --name-only <base>...HEAD` (`--since`: `<sha>..HEAD`), or whose file changed; `--all`: every entry; stems sorted. None selected: `ok` true, `routes` empty, `evidence` null. Then: Playwright lookup (`node_modules/playwright`, `node_modules/@playwright/test`, the same under `frontend/`, at the top level, no parent walk), `GET base_url` readiness up to 30 s (`DEVLOOP_TEST_READY_WAIT`, test only), each `setup` command, `storage_state` file present, one runner per entry (`node drive.mjs`, or `node <script>`; stdin `{base_url, storage_state, routes, evidence, entry, video}` (`video`: folder `<evidence>/video/<entry>/`, created), stdout `{"routes": [...]}`). Route result: `entry`, `path`, `ok`, `status`, `missing`, `console_errors`, `error`, `screenshot`, `video` (a WebM file inside the entry's `video` folder, else null; `drive.mjs`: null), `seconds`. Evidence `<git-dir>/dev-loop/evidence/<YYYYMMDDTHHMMSSZ>/` with `drive.json`. JSON `ok`, `selected`, `routes`, `evidence`, `mode` (`diff`, `since`, `all`, `before`), `head` (full sha of `HEAD`); exit 0 when `ok`. `--routes-from <file>` (a `drive.json`, the Stage 7 before run): `mode` `before`; per entry with an `ok` route, those paths, no names; only those map entries read, a missing or bad one counts as absent; a journey (an entry route with `video`) runs its own script when present, else no result; every other entry runs `drive.mjs`; a failed runner gives `ok` false, `error` `runner failed` per route, the run continues; exit 0 when it completes; exit 1: file not a JSON object with a `routes` list. Exit 1 with `error`, no route: bad `verify` or entry, `--since` not a commit, no Playwright, `base_url not reachable: <url>`, `setup command failed: <cmd>` (`tail`), `storage_state` missing, `runner failed for <stem>` (`tail`). Exit 2: two of `--all`, `--since`, `--routes-from`.
- `capture --write-after <file>`: writes the evidence after set (same walk as below) to `<file>` as `{routes, mode: diff, head, folder}`, no gh. JSON `ok`, `after`, `routes`, `head`. `verify` not an object: `skipped` `no-verify`. No `diff` drive: exit 1. Exit 2 with `--pr`, `--before` or `--after`.
- `capture --pr <n> [--before <file>] [--after <file>]`: the Stage 7 PR section. `--pr` required without `--write-after`. A string `folder` key in `--after` names the overflow folder, else the file's parent; the overflow line writes the home folder as `~`. Entry kept when a route has `ok` true; `k` is the position among all its routes; journey and its video found over all its routes. `verify` not an object: `skipped` `no-verify`, gh not called. `gh --version` below 2.99.0 or no gh: exit 1. After: `--after`, else the evidence folders (newest `diff` drive gives the entries, a newer `since` or `all` drive replaces an entry's routes, never adds one; `-capture` folders skipped). Routes with `ok` true (none: `skipped` `no-routes`). Folder `<git-dir>/dev-loop/evidence/<ts>-capture/` (a taken name gets `-capture-2`, `-capture-3`, so a recapture in the same second never overwrites; the walk skips all of them): `before-<entry>-<k>.jpg`, `after-<entry>-<k>.jpg`, `before-<entry>.webm`, `after-<entry>.webm`, `body.md`, `before.json` (the before JSON on the copies, for a recapture). Before image: same `entry` and `path`, screenshot file, `status` below 400, else `new`. Journey block when a route has a `video` file (over 10 MB: rows). Files over 10 MB left out, at most 50 files. Section between `<!-- dev-loop: captures -->` and `<!-- /dev-loop: captures -->`, replaced or appended. One `gh pr edit <n> --body-file <body.md> --attach <path> ...`. JSON `ok`, `pr`, `files`, `routes`, `omitted`, `body`, `before`. Exit 1 with `error` (`tail`): `gh pr view` or `gh pr edit` fails, bad `--before`/`--after`, no `diff` drive. Exit 2: `--pr` missing or not a positive integer.
- `audit`: SubagentStop hook JSON on stdin (`agent_id`, `agent_type`, `agent_transcript_path`, `cwd`). A re-stop replaces the agent's record or skip. JSON `taint` (record or null), `skipped`. Exit 0, also on a skip.

## Build and test

```bash
npm ci && npx playwright install chromium   # once per worktree (Chromium once per machine): the node suite drives a real browser
npm test                                    # node suite: installer, board render and drive.mjs tests
python3 tests/unit/python/test_dev_loop.py  # skill suite
```

Held-out suite: `commands.acceptance` in `dev-loop.json`, `python3 -m unittest discover -s tests/acceptance -p 'test_*.py' && node --test tests/acceptance/*.test.mjs`. CI runs it as job `acceptance`. The gate never runs it.

Skill suite runs test ids in chunks of 5 per `test_dev_loop.py --chunk` process, `DEVLOOP_TEST_JOBS` processes at a time (default one per CPU, `1`: one at a time). `DEVLOOP_REPORT_DIR` set: writes JUnit `skill.xml` there; a chunk process that dies counts each of its ids as an error. Arguments (a test name): plain unittest, no report.

`scripts/gate.sh` runs both (the full gate).

`scripts/gate.sh` fails with `run npm ci && npx playwright install chromium` when `node_modules/playwright` is missing; a new feature worktree (Stage 3 start) runs that command first. Both must pass before any commit. `.github/workflows/ci.yml` runs jobs `test` (both suites) and `acceptance` (the held-out suite) on every PR and on `main`. Merge a PR only when both checks are green.

## Conventions

- Data rule: no smaller wave, no removal of the Track L threat model and no second review pass until 5 features have a complete section in Review Yield.md (the project notes, `$NOTES/Review Yield.md`).
- Cost data rule: no process cut based on cost (drop a reviewer, no `tdd` for a task, shorter spec stages) until 5 features have a row with stage cells that are not `?` in Feature Metrics.md (`$NOTES/Feature Metrics.md`, written by `metrics --write` at Stage 7).
- Commits: gitmoji, format `<emoji>(<scope>) <message>`, scope required (e.g. `🐛(install) Back up a replaced skill outside its skills folder`).
- Changelog: `cliff.toml` (gitmoji `commit_parsers`) makes `CHANGELOG.md` and the release notes. Needs `GITHUB_TOKEN` for PR and user links. Releases are tag-driven (`vX.Y.Z`) via `.github/workflows/release.yml`: version check, `git-cliff-action`, `ncipollo/release-action`. Workflow fails when tag and `package.json` version differ.
- Release:
  1. Release PR: set `package.json` `version`, run `GITHUB_TOKEN=$(gh auth token) git cliff --tag vX.Y.Z -o CHANGELOG.md`.
  2. Run `scripts/canary.sh`, paste its lines into the release PR.
  3. Rebase the PR, no merge commit.

## Working principles

- Say your assumptions out loud. If two readings of a request lead to different work, ask before building. If a simpler approach exists, say so.
- Write the minimum code that solves the problem. No speculative abstractions, no unrequested flexibility, no error handling for impossible cases.
- Change only what the request needs. Match the surrounding style. Mention unrelated dead code rather than deleting it. Remove only the orphans your own change created.
